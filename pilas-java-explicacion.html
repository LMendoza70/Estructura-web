Pilas: solo se toca lo de arriba

Una pila es una torre de charolas: puedes poner una nueva encima o quitar la de encima, pero jamás sacar una del medio sin antes quitar todas las que están sobre ella.

Pila vacía.

LIFO: Last In, First Out — el último elemento en entrar es siempre el primero en salir.

01 · Concepto de pilas

¿Qué es una pila?

Una pila (stack) es una estructura de datos dinámica que organiza sus elementos bajo la política LIFO (Last In, First Out): el último elemento agregado es el primero en poder retirarse. Todo acceso — agregar o quitar — ocurre exclusivamente por un extremo llamado tope (top).

Analogía: imagina una torre de charolas en la cafetería. Cuando llega una charola limpia, se coloca encima de la torre. Cuando alguien necesita una, toma la de hasta arriba. Nadie saca una charola de la mitad de la torre sin antes quitar las que tiene encima. Ese comportamiento — solo tocar la de arriba — es exactamente el de una pila.
02 · Componentes

Las piezas de una pila

tope (top)

La referencia al elemento que está actualmente en la cima; es el único punto de entrada y salida de la estructura.

elementos

El conjunto de datos almacenados, cada uno "debajo" del que se agregó después de él.

estructura interna

Puede implementarse con un arreglo (con un índice que marca el tope) o, de forma dinámica, con nodos enlazados donde cada nuevo elemento se convierte en la nueva cabeza.

tamaño

La cantidad de elementos actualmente apilados; útil para saber si la pila está vacía antes de operar sobre ella.

03 · Operaciones

Lo que se le puede hacer a una pila

push(valor)

Agrega un nuevo elemento en el tope de la pila. Se convierte en el nuevo elemento más accesible.

pop()

Retira y devuelve el elemento que está en el tope. El elemento que estaba debajo pasa a ser el nuevo tope.

peek() / top()

Devuelve el valor del tope sin retirarlo de la pila. Sirve para consultar sin modificar la estructura.

isEmpty()

Indica si la pila no tiene elementos. Debe consultarse siempre antes de pop() o peek().

public class Pila<T> {

    private class Nodo {
        T dato;
        Nodo siguiente;
        Nodo(T dato) { this.dato = dato; }
    }

    private Nodo tope;
    private int tamano = 0;

    public void push(T valor) {
        Nodo nuevo = new Nodo(valor);
        nuevo.siguiente = tope;   // el nuevo nodo queda apuntando al antiguo tope
        tope = nuevo;             // y se convierte en el nuevo tope
        tamano++;
    }

    public T pop() {
        if (isEmpty()) {
            throw new IllegalStateException("La pila está vacía");
        }
        T valor = tope.dato;
        tope = tope.siguiente;    // el segundo elemento pasa a ser el nuevo tope
        tamano--;
        return valor;
    }

    public T peek() {
        if (isEmpty()) {
            throw new IllegalStateException("La pila está vacía");
        }
        return tope.dato;
    }

    public boolean isEmpty() {
        return tope == null;
    }

    public int size() {
        return tamano;
    }
}
04 · Función práctica

Dónde se usan las pilas para resolver problemas reales

Pila de llamadas (call stack)

Cada vez que un método invoca a otro, Java apila un nuevo frame; al terminar, se desapila. Es la misma idea que explica cómo funciona la recursión.

Verificar paréntesis balanceados

Al leer una expresión, cada paréntesis de apertura se apila; cada cierre debe hacer pop() y coincidir. Si al final la pila no queda vacía, la expresión está mal balanceada.

Deshacer acciones (undo)

Cada acción del usuario se apila; "deshacer" simplemente hace pop() de la última acción registrada.

Evaluación de expresiones postfijas

Los algoritmos que evalúan notación postfija (RPN) usan una pila para ir acumulando operandos hasta aplicar cada operador.

Navegación "atrás"

El botón "atrás" de un navegador apila cada página visitada; retroceder es desapilar la más reciente.

Backtracking

Algoritmos que exploran caminos y necesitan "regresar" a la última decisión (como resolver laberintos o sudokus) usan una pila para recordar el camino recorrido.

05 · Errores frecuentes

Lo que suele fallar

⚠
Hacer pop() o peek() sobre una pila vacía: sin verificar isEmpty() antes, se produce una excepción o, en implementaciones descuidadas, un comportamiento indefinido.
⚠
Confundir pila con cola: una pila es LIFO (el último en entrar es el primero en salir); una cola es FIFO (el primero en entrar es el primero en salir). Usar la estructura equivocada invierte por completo el orden de procesamiento esperado.
⚠
Olvidar actualizar el tamaño o el tope: si al implementar push()/pop() manualmente se olvida actualizar la referencia al tope, la pila queda en un estado inconsistente.
06 · Principio de Pareto

El 20% de reglas que explica el 80% de las pilas

  • Toda operación ocurre en un solo extremo: el tope. Nunca se accede al medio ni al fondo directamente.
  • LIFO: el último elemento apilado es siempre el primero en salir.
  • push() agrega arriba; pop() quita de arriba y lo devuelve; peek() solo consulta sin quitar.
  • Siempre valida isEmpty() antes de pop() o peek().
  • Si el problema involucra "regresar al paso anterior" o "deshacer lo último", casi siempre hay una pila detrás.
07 · Active recall

Ponte a prueba (haz clic en cada pregunta)

1. ¿Qué significa que una pila sea LIFO?
Que el último elemento en entrar (el más reciente) es el primero en salir. Los elementos se retiran en el orden inverso al que se agregaron.
2. ¿Cuál es la diferencia entre pop() y peek()?
pop() retira el elemento del tope y lo devuelve, modificando la pila. peek() solo devuelve el valor del tope, sin retirarlo ni modificar la estructura.
3. ¿Por qué es necesario llamar a isEmpty() antes de pop()?
Porque intentar desapilar de una pila vacía no tiene un elemento válido que retirar, y provoca una excepción (como IllegalStateException en el ejemplo) si no se valida antes.
4. Explica, usando una pila, cómo se puede verificar si los paréntesis de una expresión están balanceados.
Cada paréntesis de apertura se apila con push(); cada paréntesis de cierre hace pop() y debe coincidir con el último abierto. Si en algún punto se intenta cerrar sin nada que desapilar, o si al terminar la pila no quedó vacía, la expresión no está balanceada.
