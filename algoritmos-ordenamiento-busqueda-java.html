Ordenar, buscar y recorrer: las tres tareas que se repiten en todo programa

Casi cualquier problema termina reduciéndose a una de tres preguntas: ¿en qué orden deben quedar estos datos?, ¿dónde está el que busco?, y ¿cómo visito todos, uno por uno, sin saltarme ni repetir ninguno?

01 · Algoritmos de ordenamiento

Poner los datos en un orden específico

Un algoritmo de ordenamiento reorganiza los elementos de una colección (por ejemplo, un arreglo) según un criterio, típicamente de menor a mayor.

Ordenamiento burbuja (Bubble Sort)

Recorre el arreglo repetidamente, comparando cada pareja de elementos adyacentes y los intercambia si están en el orden incorrecto. Los valores más grandes "burbujean" hacia el final en cada pasada.

public static void ordenamientoBurbuja(int[] a) {
    for (int i = 0; i < a.length - 1; i++) {
        for (int j = 0; j < a.length - 1 - i; j++) {
            if (a[j] > a[j + 1]) {
                int temp = a[j];
                a[j] = a[j + 1];
                a[j + 1] = temp;
            }
        }
    }
}
Complejidad: O(n²) en el peor y promedio caso

Ordenamiento por selección (Selection Sort)

En cada vuelta, busca el elemento más pequeño de la parte no ordenada y lo coloca al inicio de esa parte, intercambiándolo con el que estaba ahí.

public static void ordenamientoSeleccion(int[] a) {
    for (int i = 0; i < a.length - 1; i++) {
        int indiceMenor = i;
        for (int j = i + 1; j < a.length; j++) {
            if (a[j] < a[indiceMenor]) {
                indiceMenor = j;
            }
        }
        int temp = a[i];
        a[i] = a[indiceMenor];
        a[indiceMenor] = temp;
    }
}
Complejidad: O(n²) siempre, incluso si ya está ordenado

Ordenamiento por inserción (Insertion Sort)

Construye el resultado ordenado de a poco: toma cada elemento y lo va insertando en la posición correcta dentro de la parte ya ordenada, desplazando lo necesario.

public static void ordenamientoInsercion(int[] a) {
    for (int i = 1; i < a.length; i++) {
        int actual = a[i];
        int j = i - 1;
        while (j >= 0 && a[j] > actual) {
            a[j + 1] = a[j];   // desplaza el elemento mayor una posición
            j--;
        }
        a[j + 1] = actual;
    }
}
Complejidad: O(n²) en el peor caso, O(n) si ya está casi ordenado
02 · Algoritmos de búsqueda

Encontrar un elemento dentro de una colección

Búsqueda lineal (Linear Search)

Recorre el arreglo de principio a fin comparando cada elemento con el valor buscado, hasta encontrarlo o llegar al final. Funciona con cualquier arreglo, ordenado o no.

public static int busquedaLineal(int[] a, int objetivo) {
    for (int i = 0; i < a.length; i++) {
        if (a[i] == objetivo) {
            return i;
        }
    }
    return -1;   // no se encontró
}
Complejidad: O(n)

Búsqueda binaria (Binary Search)

Requiere que el arreglo esté ordenado. Compara el elemento del medio con el valor buscado y descarta la mitad del arreglo en cada paso, repitiendo el proceso solo sobre la mitad restante.

public static int busquedaBinaria(int[] a, int objetivo) {
    int ini = 0, fin = a.length - 1;
    while (ini <= fin) {
        int medio = (ini + fin) / 2;
        if (a[medio] == objetivo) return medio;
        if (a[medio] < objetivo) ini = medio + 1;
        else fin = medio - 1;
    }
    return -1;
}
Complejidad: O(log n) — requiere arreglo ordenado
03 · Algoritmos de recorrido

Visitar todos los elementos, sin saltarse ninguno

Recorrer es visitar sistemáticamente cada elemento de una estructura exactamente una vez. En arreglos y listas es simplemente ir de principio a fin, pero en estructuras con ramificaciones (árboles, grafos) existen dos estrategias clásicas:

Recorrido en profundidad (DFS — Depth-First Search)

Avanza lo más posible por una rama antes de retroceder. Se apoya naturalmente en una pila (explícita o mediante recursión, que usa la pila de llamadas).

Recorrido en anchura (BFS — Breadth-First Search)

Visita todos los elementos de un mismo "nivel" antes de pasar al siguiente. Se apoya naturalmente en una cola: se encolan los vecinos y se procesan en el orden en que fueron descubiertos.

Conexión con lo ya visto: DFS y BFS no son más que aplicaciones directas de las estructuras que ya conoces — DFS usa la disciplina LIFO de una pila, BFS usa la disciplina FIFO de una cola. La elección de estructura determina el orden de recorrido.
04 · Complejidad algorítmica

¿Qué tan rápido crece el trabajo?

La complejidad algorítmica, expresada en notación Big-O, describe cómo crece el tiempo (o la memoria) que un algoritmo necesita a medida que crece el tamaño de la entrada n. No mide segundos exactos: mide la tendencia de crecimiento.

NotaciónNombreEjemplo de este documento
O(1)ConstanteAcceder a arreglo[i] por índice
O(log n)LogarítmicaBúsqueda binaria
O(n)LinealBúsqueda lineal, recorrido de un arreglo
O(n²)CuadráticaBurbuja, selección, inserción

Por eso, para un arreglo grande, una búsqueda binaria (O(log n)) es dramáticamente más rápida que una lineal (O(n)) — pero solo funciona si el arreglo ya está ordenado, y ordenarlo con un algoritmo básico cuesta O(n²). Esa es la decisión de fondo detrás de elegir un algoritmo: no hay una opción que gane siempre, depende de los datos y de cuántas veces se repetirá la operación.

05 · Errores frecuentes

Lo que suele fallar

⚠
Usar búsqueda binaria sobre un arreglo no ordenado: el algoritmo asume orden; sin él, descarta mitades incorrectas y puede fallar en encontrar un elemento que sí está presente.
⚠
Confundir "más código" con "más lento": la complejidad no depende de cuántas líneas tiene el algoritmo, sino de cómo escala el número de operaciones cuando n crece.
⚠
Elegir burbuja o selección para arreglos grandes: ambos son O(n²); para volúmenes de datos grandes conviene un algoritmo de ordenamiento más eficiente (como Merge Sort o Quick Sort, O(n log n)), fuera del alcance de esta guía introductoria.
06 · Principio de Pareto

El 20% de reglas que explica el 80% del tema

  • Ordenar es reorganizar; buscar es localizar; recorrer es visitar todo sin repetir ni saltar.
  • Búsqueda binaria (O(log n)) solo funciona sobre datos ya ordenados; búsqueda lineal (O(n)) funciona siempre.
  • Los tres algoritmos de ordenamiento básicos (burbuja, selección, inserción) son O(n²): útiles para aprender la lógica, no para producción con datos grandes.
  • DFS se apoya en una pila (LIFO); BFS se apoya en una cola (FIFO) — la estructura determina el orden de recorrido.
  • La notación Big-O describe tendencia de crecimiento, no tiempo exacto en segundos.
07 · Active recall

Ponte a prueba (haz clic en cada pregunta)

1. ¿Por qué la búsqueda binaria requiere que el arreglo esté ordenado?
Porque en cada paso decide qué mitad descartar comparando el elemento del medio con el objetivo; si el arreglo no está ordenado, esa comparación no garantiza que el valor buscado esté en la mitad que se conserva.
2. ¿Qué tienen en común burbuja, selección e inserción en cuanto a complejidad?
Los tres son O(n²) en el peor caso: el trabajo crece proporcionalmente al cuadrado del tamaño de la entrada.
3. ¿Qué estructura de datos usa naturalmente un recorrido BFS, y cuál usa un DFS?
BFS usa una cola (FIFO), procesando nivel por nivel. DFS usa una pila (o recursión, que internamente usa la pila de llamadas), avanzando lo más posible por una rama antes de retroceder.
4. Si tienes un arreglo de un millón de elementos y necesitas buscar muchas veces en él, ¿qué conviene más: ordenarlo una vez y usar búsqueda binaria, o dejarlo desordenado y usar búsqueda lineal cada vez?
Casi siempre conviene ordenarlo una vez (aunque cueste O(n log n) con un algoritmo eficiente, o O(n²) con uno básico) y luego aprovechar múltiples búsquedas binarias en O(log n) cada una — mucho más rápido que repetir búsquedas lineales en O(n) cada vez.
