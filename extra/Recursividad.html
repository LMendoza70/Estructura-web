1. Definición esencial

La recursividad es una técnica de programación en la que un método se invoca a sí mismo para resolver un problema dividiéndolo en subproblemas más pequeños del mismo tipo, hasta alcanzar un caso base trivial que detiene la cadena de llamadas; se utiliza para procesar estructuras jerárquicas (árboles, directorios, grafos) y en algoritmos como búsqueda, ordenamiento y backtracking.

2. Analogía simple

Imagina que tienes una clase Empleado con un atributo jefe (también de tipo Empleado). Quieres saber cuántos niveles jerárquicos hay por encima de ti hasta llegar al CEO. Podrías escribir un método nivelesHastaCEO() que funcione así:

// Método recursivo dentro de la clase Empleado
public int nivelesHastaCEO() {
    // Caso base: soy el CEO, no hay nadie por encima
    if (this.jefe == null) {
        return 0;
    } else {
        // Caso recursivo: pregunto a mi jefe y sumo 1
        return 1 + this.jefe.nivelesHastaCEO();
    }
}

Cada objeto Empleado ejecuta el mismo método, pero con sus propios datos. El empleado de base le pregunta a su jefe, ese jefe le pregunta a su jefe, y así hasta llegar al CEO, que responde 0. Luego las respuestas se van sumando de regreso.

Esta analogía conecta directamente con la programación orientada a objetos: cada objeto cumple un "contrato" (el método), y para cumplirlo puede delegar la misma responsabilidad en otro objeto de su misma clase. La recursividad es, en esencia, un objeto (o método) que se llama a sí mismo a través de una cadena de delegaciones.

3. División en partes pequeñas

Parte 1: Caso base y caso recursivo

Definición breve: Todo método recursivo debe tener al menos una condición que detenga la recursión (caso base) y una llamada a sí mismo con una versión reducida del problema (caso recursivo). Sin caso base, el método se llamaría infinitamente y provocaría un desbordamiento de pila.

// Ejemplo: factorial
public class Calculadora {
    public static long factorial(int n) {
        // Caso base: si n es 0, la respuesta es 1
        if (n == 0) {
            return 1;
        }
        // Caso recursivo: n! = n * (n-1)!
        return n * factorial(n - 1);
    }
}

La condición if (n == 0) actúa como el "contrato del caso base". En el caso recursivo, reducimos el problema: factorial(n - 1) es una versión más pequeña.

Parte 2: La pila de llamadas y el orden de ejecución

Definición breve: Cada vez que un método se llama a sí mismo, se crea un nuevo marco de pila (stack frame) que contiene variables locales y punto de retorno. Las llamadas se apilan y se resuelven en orden inverso (LIFO).

Con factorial(3):

  1. factorial(3) espera a factorial(2).
  2. factorial(2) espera a factorial(1).
  3. factorial(1) espera a factorial(0).
  4. factorial(0) devuelve 1.
  5. Se desenrolla: 1*1=1, 2*1=2, 3*2=6.

Puedes imaginar que cada llamada recursiva es como crear un nuevo objeto de una clase interna con su propia variable n y su propio contexto. La pila de llamadas mantiene separados estos contextos, igual que dos instancias de una clase tienen atributos independientes.

Parte 3: Diseño de métodos recursivos (pensar en subproblemas)

Definición breve: Para escribir un método recursivo, no simules toda la cadena. Sigue tres pasos: 1) identifica el caso base, 2) expresa el problema en términos de una versión más pequeña, 3) confía en que la llamada recursiva resuelve el subproblema (hipótesis de inducción).

// Ejemplo: contar nodos en lista enlazada
class Nodo {
    int valor;
    Nodo siguiente;

    Nodo(int valor, Nodo siguiente) {
        this.valor = valor;
        this.siguiente = siguiente;
    }

    // Método recursivo para contar nodos desde este nodo
    int contar() {
        // Caso base: si no hay siguiente, este nodo es el último
        if (this.siguiente == null) {
            return 1;
        }
        // Caso recursivo: cuento este nodo + los del resto
        return 1 + this.siguiente.contar();
    }
}

Este diseño refleja la delegación en POO: un objeto no resuelve todo el problema, pide a otro objeto de su misma clase que resuelva una parte.

Parte 4: Recursión vs iteración y recursión de cola

Definición breve: Cualquier problema recursivo puede reescribirse con bucles y viceversa. La recursión brilla en estructuras ramificadas (árboles, grafos). La recursión de cola ocurre cuando la llamada recursiva es la última operación; algunos lenguajes la optimizan, pero Java no lo hace automáticamente.

// Factorial iterativo
public static long factorialIterativo(int n) {
    long resultado = 1;
    for (int i = 1; i <= n; i++) {
        resultado *= i;
    }
    return resultado;
}

// Factorial recursivo de cola (con acumulador)
public static long factorialCola(int n, long acumulador) {
    if (n == 0) return acumulador;
    return factorialCola(n - 1, n * acumulador);
}

En Java, la recursión de cola no está optimizada, así que para problemas lineales muy profundos se prefiere la iteración. Pero para problemas jerárquicos, la recursión es mucho más clara.

4. Los 3 errores más comunes

Error 1: Olvidar el caso base o definirlo incorrectamente

Por qué ocurre: Al concentrarse en el caso recursivo, se olvida la condición de parada o nunca se alcanza.

Cómo evitarlo: Antes de escribir la llamada recursiva, pregúntate cuál es la versión más pequeña y trivial del problema. Escríbela primero como un if que devuelve un valor constante. Luego asegúrate de que cada llamada reduce el problema hacia ese caso base.

Error 2: Intentar seguir mentalmente toda la cadena de llamadas

Por qué ocurre: Querer "ejecutar" paso a paso cada llamada satura la memoria de trabajo.

Cómo evitarlo: Adopta el pensamiento inductivo: asume que tu método ya funciona para entradas más pequeñas y solo combina esa solución con el caso actual. Verifica el caso base por separado. Es como confiar en un método de otra clase sin mirar su implementación.

Error 3: Creer que las variables se comparten entre llamadas recursivas

Por qué ocurre: Acostumbrados a que los atributos de un objeto persisten, piensan que una variable local es la misma en todas las llamadas.

Cómo evitarlo: Recuerda que cada llamada tiene sus propias copias de parámetros y variables locales (marcos de pila separados). Si necesitas acumular, pásalo como parámetro o usa atributos de instancia (aunque introduce estado mutable).

5. Preguntas de verificación

Haz clic en "Mostrar respuesta" para ver la solución y la explicación.

Pregunta 1

¿Cuál es el caso base en el siguiente método?

public static int sumaDigitos(int n) {
    if (n < 10) return n;
    return n % 10 + sumaDigitos(n / 10);
}

A) n % 10   B) n < 10   C) sumaDigitos(n / 10)   D) No tiene caso base

Respuesta correcta: B) n < 10

Si fallas: El caso base es la condición que detiene la recursión. Aquí, cuando el número tiene un solo dígito, se devuelve ese dígito sin más recursión.

Pregunta 2

Verdadero o falso: En una llamada recursiva, las variables locales del método son compartidas entre todas las llamadas.

Falso. Cada llamada recursiva tiene su propio conjunto de variables locales en un marco de pila separado, igual que dos objetos de una clase tienen sus propios atributos.

Pregunta 3

¿Qué ocurre si olvidas el caso base en un método recursivo?

A) El programa compila pero devuelve 0.   B) Se lanza StackOverflowError.   C) El compilador lo detecta.   D) El método se ejecuta una sola vez.

Respuesta correcta: B) Se lanza StackOverflowError

Si fallas: Sin caso base, cada llamada genera otra, llenando la pila hasta agotar la memoria.

Pregunta 4

Dado el siguiente método recursivo, ¿qué devuelve misterio(3)?

public static int misterio(int n) {
    if (n == 0) return 0;
    return n + misterio(n - 1);
}

A) 6   B) 3   C) 0   D) 1

Respuesta correcta: A) 6 (suma 3 + 2 + 1 + 0)

Si fallas: Simula la pila: misterio(3) espera a misterio(2), que espera a misterio(1), que espera a misterio(0). Luego se suman al desenrollar.

Pregunta 5

¿Cuál de las siguientes afirmaciones sobre recursión es correcta?

A) La recursión siempre es más eficiente que la iteración.   B) La recursión solo sirve para factoriales.   C) Cualquier problema iterativo se puede expresar recursivamente y viceversa.   D) En Java, la recursión de cola está optimizada automáticamente.

Respuesta correcta: C)

Si fallas: La recursión no es intrínsecamente más rápida (usa más memoria por la pila). En Java no hay optimización automática de recursión de cola. La recursión es preferible en estructuras jerárquicas.

6. Ejemplos prácticos

Ejemplo en clase 1: Factorial recursivo (introducción)

Momento de la clase: Al inicio, justo después de explicar caso base y caso recursivo.

// EjemploFactorial.java
public class EjemploFactorial {

    /** Calcula el factorial de n de forma recursiva. */
    public static long factorial(int n) {
        // Caso base: 0! = 1
        if (n == 0) {
            return 1;
        }
        // Caso recursivo: n! = n * (n-1)!
        return n * factorial(n - 1);
    }

    public static void main(String[] args) {
        int numero = 5;
        long resultado = factorial(numero);
        System.out.println("El factorial de " + numero + " es " + resultado);
    }
}

Explicación paso a paso: main llama a factorial(5); como 5 != 0, se ejecuta return 5 * factorial(4). Esto continúa hasta factorial(0) que devuelve 1. Luego se desenrolla: 1*1=1, 2*1=2, ..., 5*24=120.

Qué resaltar: Importancia del caso base, reducción del problema, y que la multiplicación ocurre después de que la llamada recursiva retorna.

Ejemplo en clase 2: Recorrido de árbol binario

Momento de la clase: Después de la Parte 3, para mostrar recursión natural en estructuras jerárquicas.

// Clase NodoArbol con inserción y recorrido recursivos
class NodoArbol {
    int valor;
    NodoArbol izquierdo;
    NodoArbol derecho;

    NodoArbol(int valor) {
        this.valor = valor;
        this.izquierdo = null;
        this.derecho = null;
    }

    // Inserción recursiva
    void insertar(int nuevoValor) {
        if (nuevoValor < this.valor) {
            if (this.izquierdo == null) {
                this.izquierdo = new NodoArbol(nuevoValor);
            } else {
                this.izquierdo.insertar(nuevoValor);
            }
        } else if (nuevoValor > this.valor) {
            if (this.derecho == null) {
                this.derecho = new NodoArbol(nuevoValor);
            } else {
                this.derecho.insertar(nuevoValor);
            }
        }
        // Si es igual, no se hace nada (evita duplicados)
    }

    // Recorrido inorden recursivo: izquierdo, raíz, derecho
    void imprimirInorden() {
        if (this.izquierdo != null) {
            this.izquierdo.imprimirInorden();
        }
        System.out.print(this.valor + " ");
        if (this.derecho != null) {
            this.derecho.imprimirInorden();
        }
    }
}

public class EjemploArbol {
    public static void main(String[] args) {
        NodoArbol raiz = new NodoArbol(50);
        raiz.insertar(30);
        raiz.insertar(70);
        raiz.insertar(20);
        raiz.insertar(40);
        raiz.insertar(60);
        raiz.insertar(80);

        System.out.println("Recorrido inorden:");
        raiz.imprimirInorden();  // 20 30 40 50 60 70 80
    }
}

Qué resaltar: La recursión permite expresar el algoritmo en términos del propio árbol. Cada objeto delega a otros de su misma clase. La alternativa iterativa requeriría una pila explícita.

Práctica para el alumno

Enunciado: Búsqueda binaria recursiva

Implementa un método recursivo que realice una búsqueda binaria sobre un arreglo ordenado de enteros. Firma:

public static int busquedaBinaria(int[] arreglo, int objetivo, int inicio, int fin)

Debe devolver el índice del elemento si lo encuentra, o -1 si no está. No puedes usar bucles; la solución debe ser recursiva.

Objetivos de aprendizaje: Identificar caso base, definir caso recursivo reduciendo a la mitad, confiar en la llamada recursiva, manejar índices correctamente.

Pista: Caso base: si inicio > fin, subarreglo vacío. Calcula medio, compara, y llama recursivamente con fin = medio - 1 o inicio = medio + 1. Devuelve el resultado de la llamada recursiva.

Solución de referencia (para el profesor):

public static int busquedaBinaria(int[] arreglo, int objetivo, int inicio, int fin) {
    if (inicio > fin) return -1;
    int medio = (inicio + fin) / 2;
    if (arreglo[medio] == objetivo) return medio;
    if (objetivo < arreglo[medio])
        return busquedaBinaria(arreglo, objetivo, inicio, medio - 1);
    else
        return busquedaBinaria(arreglo, objetivo, medio + 1, fin);
}

Advertencia sobre malas prácticas de enseñanza

Un error común en muchos cursos es presentar la recursividad únicamente con ejemplos lineales como factorial o Fibonacci. Esto lleva a pensar que la recursión es una alternativa rebuscada e ineficiente a los bucles. Si solo ves factorial recursivo, es lógico preguntarse: "¿por qué no usar un simple for?".

Otro enfoque equivocado es obligar a los estudiantes a simular manualmente cada paso de la pila para programas recursivos complejos. Si bien entender la pila es importante, obsesionarse con el seguimiento paso a paso impide desarrollar el pensamiento inductivo: confiar en que la llamada recursiva resuelve el subproblema.

Además, algunos profesores afirman que "la recursión es mala porque llena la pila" sin matizar. Si bien es cierto que una recursión profunda puede causar StackOverflowError, en problemas con estructuras jerárquicas (árboles balanceados, directorios, divide y vencerás) la profundidad es logarítmica o acotada, y la recursión es la solución más natural y mantenible.

Desde el principio, entiende que la recursividad es una herramienta de diseño, no una simple técnica de control de flujo. Es la manera natural de expresar soluciones para problemas con estructura autorreplicante.
