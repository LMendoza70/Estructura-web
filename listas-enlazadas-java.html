Estructuras de datos dinámicas: listas enlazadas

Mientras un arreglo es un tren con vagones fijos y soldados entre sí, una lista enlazada es una cadena de vagones sueltos que se enganchan y desenganchan sobre la marcha, según se necesite.

Cada nodo aparece en una dirección de memoria distinta y no contigua; lo único que los conecta es la referencia que guarda cada nodo hacia el siguiente (y, en la doble, también hacia el anterior).

01 · Concepto de estructura de datos dinámica

¿Qué es una estructura de datos dinámica?

Es una estructura cuyo tamaño no se fija de antemano: la memoria para cada uno de sus elementos se reserva en tiempo de ejecución, a medida que el programa los va necesitando, y se libera cuando ya no se usan.

Analogía: un arreglo es como un tren con vagones soldados de fábrica: si compraste un tren de 6 vagones, siempre serán 6, estén ocupados o no. Una estructura dinámica es un tren de vagones sueltos: enganchas uno nuevo cuando llega un pasajero, y lo desenganchas cuando ya no se usa. El tren crece y se encoge según la demanda real.
02 · Características

Lo que distingue a una estructura dinámica de un arreglo

Tamaño variable

Crece o se reduce mientras el programa se ejecuta, sin necesidad de declarar un límite máximo por adelantado.

Memoria no contigua

Cada elemento (nodo) puede vivir en cualquier parte de la memoria; lo que los mantiene unidos son referencias explícitas, no la cercanía física.

Inserción/eliminación eficiente

Agregar o quitar un elemento en medio de la estructura no requiere desplazar a los demás, como sí ocurre en un arreglo.

Acceso secuencial

Para llegar al elemento 5 hay que pasar por el 1, 2, 3 y 4 primero: no existe acceso directo por índice como en un arreglo.

03 · Metodología de codificación

Las dos clases que forman toda estructura dinámica

En Java, una estructura dinámica se construye siempre con el mismo patrón: una clase Nodo que guarda un dato y una o más referencias a otros nodos, y una clase contenedora que administra el punto de entrada (la cabeza) y las operaciones sobre el conjunto.

// Pieza 1: el nodo — la unidad mínima de la estructura
public class Nodo<T> {
    T dato;
    Nodo<T> siguiente;

    public Nodo(T dato) {
        this.dato = dato;
        this.siguiente = null;
    }
}

// Pieza 2: la lista — administra el punto de entrada y las operaciones
public class ListaEnlazada<T> {
    private Nodo<T> cabeza;

    public void insertarFinal(T valor) {
        Nodo<T> nuevo = new Nodo<>(valor);
        if (cabeza == null) {
            cabeza = nuevo;
            return;
        }
        Nodo<T> actual = cabeza;
        while (actual.siguiente != null) {
            actual = actual.siguiente;   // avanzar hasta el último nodo
        }
        actual.siguiente = nuevo;
    }

    public void recorrer() {
        Nodo<T> actual = cabeza;
        while (actual != null) {
            System.out.println(actual.dato);
            actual = actual.siguiente;
        }
    }
}

Todas las operaciones (insertar, eliminar, buscar, recorrer) se reducen a manipular estas referencias: nunca se mueve el contenido de un nodo, solo se reconectan los enlaces entre ellos.

04 · Concepto de listas

¿Qué es una lista enlazada?

Una lista enlazada es la estructura dinámica más básica: una secuencia de nodos donde cada nodo conoce (mediante una referencia) cuál es el siguiente. La lista en sí solo necesita recordar un punto de partida — la cabeza — para poder llegar a todos los demás nodos siguiendo la cadena de referencias.

05 · Tipos de listas

Simples, dobles y circulares

Lista simple

Cada nodo apunta solo hacia adelante. Para retroceder no hay forma directa: habría que volver a recorrer desde la cabeza.

class Nodo<T> {
    T dato;
    Nodo<T> siguiente;   // una sola referencia
}

Uso práctico: pilas y colas simples, listas de reproducción sin retroceso, historial de deshacer de un solo sentido.

Lista doble

Cada nodo guarda referencia tanto al siguiente como al anterior, permitiendo recorrer la lista en ambas direcciones.

class NodoDoble<T> {
    T dato;
    NodoDoble<T> siguiente;
    NodoDoble<T> anterior;   // referencia extra hacia atrás
}

Uso práctico: historial de navegación (adelante/atrás), reproductores de música con "anterior" y "siguiente", edición de texto con deshacer/rehacer en ambos sentidos.

Lista circular

El último nodo, en vez de apuntar a null, apunta de regreso a la cabeza — la cadena nunca "termina", forma un círculo. Puede ser circular simple o circular doble.

// Al insertar el último nodo, en vez de dejar null:
ultimo.siguiente = cabeza;   // cierra el círculo

Uso práctico: turnos rotativos (round-robin) entre procesos o jugadores, listas de reproducción en modo "repetir todo", buffers circulares.

06 · Errores frecuentes

Lo que suele fallar

⚠
No verificar si la cabeza es null: intentar recorrer o insertar sin comprobar primero si la lista está vacía provoca un NullPointerException.
⚠
Perder la referencia a la cabeza: si reasignas la variable que apunta a la cabeza antes de haber recorrido o guardado la lista, pierdes el acceso a todos los nodos siguientes: quedan "flotando" en memoria sin forma de alcanzarlos.
⚠
Bucle infinito al recorrer una lista circular: la condición clásica while (actual != null) nunca se cumple en una lista circular, porque ningún nodo apunta a null. Hay que detenerse cuando se vuelve a llegar a la cabeza.
07 · Principio de Pareto

El 20% de reglas que explica el 80% de las listas enlazadas

  • Todo se reduce a dos piezas: el Nodo (dato + referencia(s)) y la lista que guarda la cabeza y las operaciones.
  • Insertar o eliminar es reconectar referencias, nunca mover datos de lugar.
  • Simple = una referencia (adelante); Doble = dos referencias (adelante y atrás); Circular = el último nodo vuelve al primero.
  • Siempre revisa primero si la cabeza es null antes de recorrer o modificar la lista.
  • En una lista circular, la condición de paro del recorrido es "volví a la cabeza", no "llegué a null".
08 · Active recall

Ponte a prueba (haz clic en cada pregunta)

1. ¿Cuál es la diferencia clave entre la memoria de un arreglo y la de una lista enlazada?
El arreglo usa un bloque de memoria contiguo y de tamaño fijo; la lista enlazada usa nodos dispersos por la memoria, conectados mediante referencias, y puede crecer o encogerse en tiempo de ejecución.
2. ¿Qué campo adicional tiene un nodo de lista doble que no tiene uno de lista simple?
Una referencia anterior, que apunta al nodo previo, además de la referencia siguiente que ya tenía la lista simple.
3. ¿Qué distingue a una lista circular de una lista simple?
En la lista circular, el último nodo no apunta a null: apunta de regreso a la cabeza, cerrando el círculo. En la simple, el último nodo apunta a null.
4. ¿Por qué usar while (actual != null) para recorrer una lista circular provoca un bucle infinito?
Porque en una lista circular ningún nodo tiene una referencia null: el último siempre apunta de vuelta a la cabeza, así que la condición nunca se vuelve falsa por sí sola.
5. Da un ejemplo práctico donde convenga más una lista circular que una simple.
Un sistema de turnos rotativos (round-robin) entre varios procesos o jugadores, donde después del último elemento se debe volver automáticamente al primero sin reiniciar el recorrido manualmente.
