01 · Concepto

La instrucción while: repetir mientras la condición sea verdadera

Una instrucción de repetición (ciclo o loop) le permite al programa repetir una acción mientras cierta condición sea verdadera. Es la tercera estructura de control de la programación estructurada —la que la página de condicionales dejó pendiente.

Analogía (Feynman): la lista de compras del libro. "Mientras existan más artículos en mi lista, compro el siguiente artículo y lo quito de la lista." La condición puede ser verdadera o falsa; mientras lo sea, la acción se repite. Cuando la lista queda vacía (condición falsa), sales de la tienda y sigues con el resto del día: ese "resto del día" es la primera instrucción después del ciclo.

La instrucción (o instrucciones) que se repite se llama cuerpo del ciclo. Cada ejecución completa del cuerpo se llama iteración. Java evalúa la condición antes de cada iteración, por eso a while se le llama repetición controlada por la condición y puede ejecutar cero o más veces.

Primer ejemplo: la primera potencia de 3 mayor que 100

int producto = 3;

while ( producto <= 100 )
    producto = 3 * producto;

Arrancando con producto = 3, cada iteración la multiplica por 3: 9, 27, 81, 243. Al volver producto = 243, la condición producto <= 100 es falsa, el ciclo termina y la ejecución continúa con la siguiente instrucción. Resultado: 243.

✓Seudocódigo: Mientras existan más artículos en mi lista de compras  Comprar el siguiente artículo y quitarlo de mi lista. En seudocódigo no se usan llaves: la sangría basta para indicar el cuerpo. En Java, la llave de apertura { es la que delimita el cuerpo.
⚠Detalle del libro (p. 122): el texto menciona una vez la condición producto <= 1000, pero el código y el resultado 243 corresponden a producto <= 100. Con 1000 seguiría hasta 729. Corrige la nota al margen de tu libro.

Tres palabras clave nuevas: while (repetición), do y for — las últimas dos llegan en el capítulo 5. En esta página todo se resuelve con while, que es la base de las otras dos.

02 · Anatomía

Las tres fases de todo ciclo (y su diagrama de actividad)

Todo programa con ciclos se divide lógicamente en tres fases. Nombrarlas es la manera más rápida de detectar un ciclo roto:

1 · Inicialización

Se preparan las variables antes de tocar el ciclo: totales en 0, contadores en 0 o 1, y la primera lectura de datos cuando el ciclo es por centinela.

2 · Procesamiento

El cuerpo del while: leer, sumar, contar y —lo fundamental— cambiar algo para que la condición acabe siendo falsa.

3 · Terminación

Lo que ocurre después del ciclo: calcular el promedio, imprimir el reporte, avisar que no hubo datos.

El contrato del ciclo

Condición entre ( ) de tipo boolean + cuerpo con llaves + una acción que acerque a la condición a ser falsa. Si falta la tercera, hay ciclo infinito.

Diagrama de actividad UML del while (fig. 4.4): la fusión junta el flujo que entra desde el inicio y el que regresa desde el cuerpo; la decisión es la que se evalúa al comienzo de cada iteración y tiene dos flechas de salida con condición de guardia.
Decisión vs. fusión: los dos son rombos, pero se distinguen por las flechas. Un símbolo de decisión tiene 1 entrada y 2 o más salidas (cada salida con su guardia). Un símbolo de fusión tiene 2 o más entradas y 1 sola salida, y ninguna de sus flechas lleva guardia.
03 · Repetición controlada por contador

Saber de antemano cuántas vueltas faltan

La repetición controlada por contador (o repetición definida) usa una variable contador que se incrementa en cada iteración; el ciclo termina cuando el contador excede el número de vueltas. En este ejemplo se sabe de entrada: 10 estudiantes.

Dos términos del libro: un total es una variable que acumula la suma de varios valores; un contador es una variable que cuenta. Los totales se inicializan en 0; los contadores, en 0 o 1 según cómo se usen.

La implementación completa es la clase LibroCalificaciones del capítulo 3, con un método nuevo. Este es el corazón del método determinarPromedioClase() (fig. 4.6):

import java.util.Scanner;   // el programa usa la clase Scanner

public void determinarPromedioClase()
{
    Scanner entrada = new Scanner( System.in );

    int total;          // suma de las calificaciones
    int contadorCalif;  // número de la siguiente calificación
    int calificacion;   // valor escrito por el usuario
    int promedio;       // promedio de las calificaciones

    // fase de inicialización
    total = 0;
    contadorCalif = 1;

    // fase de procesamiento
    while ( contadorCalif <= 10 )   // itera 10 veces
    {
        System.out.print( "Escriba la calificación: " );
        calificacion = entrada.nextInt();      // lee la calificación
        total = total + calificacion;          // la suma al total
        contadorCalif = contadorCalif + 1;   // avanza el contador
    }

    // fase de terminación
    promedio = total / 10;   // ¡división entera!

    System.out.printf( "\nEl total de las 10 calificaciones es %d\n", total );
    System.out.printf( "El promedio de la clase es %d\n", promedio );
}

04 · Repetición controlada por un centinela

Cuando no sabes cuántas vueltas habrá

¿Y si el problema dice "para un número arbitrario de estudiantes"? El programa no sabe de antemano cuántas calificaciones vendrán. La solución es un valor centinela (también llamado valor de señal, de prueba o de bandera): un valor especial que el usuario teclea para indicar "ya no hay más datos". Como el número de repeticiones no se conoce de entrada, a esto se le llama repetición indefinida.

El centinela debe ser un valor imposible en los datos: las calificaciones son enteros de 0 a 100, así que -1 sirve perfectamente. Si eligieras 0 como centinela y alguien saca 0, el programa creería que ya terminaste: ese es el Error común 4.6.

Del problema al código: refinamiento de arriba a abajo

El libro construye este algoritmo con refinamiento paso a paso: primero la cima (una sola frase), luego tareas más pequeñas, hasta tener seudocódigo traducible a Java. Fíjate en que la primera lectura va FUERA del ciclo, para poder evaluarla antes de entrar:

La traducción a Java de ese seudocódigo es el método determinarPromedioClase() de la fig. 4.9 — esta es la versión que usa el banco de pruebas de arriba (pestaña ciclo con centinela):

import java.util.Scanner;

public void determinarPromedioClase()
{
    Scanner entrada = new Scanner( System.in );

    int total;
    int contadorCalif;
    int calificacion;
    double promedio;   // ahora sí: puede tener decimales

    // fase de inicialización
    total = 0;
    contadorCalif = 0;

    // fase de procesamiento
    System.out.print( "Escriba calificación o -1 para terminar: " );
    calificacion = entrada.nextInt();   // ¡fuera del ciclo!

    while ( calificacion != -1 )   // itera hasta el centinela
    {
        total = total + calificacion;
        contadorCalif = contadorCalif + 1;

        System.out.print( "Escriba calificación o -1 para terminar: " );
        calificacion = entrada.nextInt();
    }

    // fase de terminación
    if ( contadorCalif != 0 )   // evita la división entre cero
    {
        promedio = (double) total / contadorCalif;

        System.out.printf( "\nEl total de las %d calificaciones introducidas es %d\n",
            contadorCalif, total );
        System.out.printf( "El promedio de la clase es %.2f\n", promedio );
    }
    else
        System.out.println( "No se introdujeron calificaciones" );
}

05 · Instrucciones anidadas

Un if...else dentro de un while

Las instrucciones de control se conectan de dos maneras: apilándose (una tras otra, como en la sección 04) o anidándose (una dentro de otra). Este ejemplo —resultados de un examen— usa las dos a la vez: un if...else dentro de un while, y después un if simple después del ciclo.

Apilamiento

El punto de salida de una estructura se une al punto de entrada de la siguiente. Se ejecutan, en ese orden, las que hagan falta.

Anidamiento

Una estructura de control vive dentro del cuerpo de otra. El if interior se evalúa una vez por cada iteración del while exterior.

Seudocódigo de la fig. 4.11 y su conversión a la clase Analisis (fig. 4.12):

import java.util.Scanner;

public class Analisis
{
    public void procesarResultadosExamen()
    {
        Scanner entrada = new Scanner( System.in );

        // inicialización incluida en la declaración
        int aprobados = 0;
        int reprobados = 0;
        int contadorEstudiantes = 1;
        int resultado;

        while ( contadorEstudiantes <= 10 )
        {
            System.out.print( "Escriba el resultado (1 = aprobado, 2 = reprobado): " );
            resultado = entrada.nextInt();

            // if...else anidado en while
            if ( resultado == 1 )
                aprobados = aprobados + 1;
            else
                reprobados = reprobados + 1;

            contadorEstudiantes = contadorEstudiantes + 1;
        }

        // fase de terminación
        System.out.printf( "Aprobados: %d\nReprobados: %d\n", aprobados, reprobados );

        if ( aprobados > 8 )
            System.out.println( "Aumentar colegiatura" );
    }
}

06 · Azúcar sintáctico

Operadores de asignación compuestos (+=, -=, *=, /=, %=)

Toda instrucción de la forma variable = variable operador expresión; puede abreviarse. Si operador es uno de +, -, *, / o %, escribes variable operador= expresión;.

// larga
total = total + calificacion;

// corta (idéntica)
total += calificacion;
OperadorEjemploEquivale aAsigna
+=c += 7c = c + 710 a c
-=d -= 4d = d - 41 a d
*=e *= 5e = e * 520 a e
/=f /= 3f = f / 32 a f
%=g %= 9g = g % 93 a g

Suponiendo int c = 3, d = 5, e = 4, f = 6, g = 12; (fig. 4.14). Nota que f /= 3 es división entera: 6 / 3 = 2 exacto; con 7 / 3 daría 2, no 2.33.

✓Los compuestos funcionan con cualquier operador binario, no solo con aritméticos: en capítulos posteriores verás &=, |=, >>=, etc. Regla general: si la variable aparece dos veces (una a la izquierda del = y otra dentro de la expresión), casi siempre cabe en un operador compuesto.
⚠Cuidado con la asignación dentro de una condición: while ( (calificacion = entrada.nextInt()) != -1 ) es válido en Java y se ve en código avanzado, pero mezcla leer y comparar en una sola línea. En este curso escribe las dos instrucciones por separado: se lee mucho mejor.
07 · ++ y --

Los operadores de incremento y decremento

Para sumar o restar 1 a una variable numérica, Java tiene dos operadores unarios (de un solo operando): ++ y --. Donde escribirías c = c + 1 o c += 1, escribes c++.

OperadorSe llamaEjemploQué hace
++Preincremento++aIncrementa a en 1 y después usa el nuevo valor en la expresión.
++Postincrementoa++Usa primero el valor actual de a en la expresión y después lo incrementa.
--Predecremento--bDecrementa b en 1 y después usa el nuevo valor.

La clase Incremento (fig. 4.16) muestra la diferencia — un ejemplo "mecánico" de una sola clase, todo dentro de main:

public class Incremento
{
    public static void main( String args[] )
    {
        int c;

        // demuestra el operador de postincremento
        c = 5;
        System.out.println( c );          // imprime 5
        System.out.println( c++ );        // imprime 5, DESPUÉS incrementa
        System.out.println( c );          // imprime 6

        System.out.println();             // omite una línea

        // demuestra el operador de preincremento
        c = 5;
        System.out.println( c );          // imprime 5
        System.out.println( ++c );        // incrementa y DESPUÉS imprime 6
        System.out.println( c );          // imprime 6
    }
}

¿Cuándo importa la diferencia? Si la instrucción es c++; o ++c; por sí sola, ambas hacen exactamente lo mismo: sumar 1 a c. Solo cambian cuando la variable aparece dentro de una expresión más grande —como System.out.println( c++ ), donde el valor que se imprime es el anterior.

Las tres formas de "sumar uno" (ya las conoces)

++aprobados;                  // preincremento

// las cuatro hacen lo mismo aquí
⚠Error común 4.9: ++(x + 1) es error de sintaxis: el operando de ++ debe ser una variable a la que se le pueda asignar un valor, no una expresión. Del mismo modo, ++c; sin espacios: los operadores unarios van pegados a su operando (Buena práctica 4.7) — + +c no tiene sentido.

08 · Marco teórico

Los ocho tipos primitivos de Java

Java es un lenguaje fuertemente tipado: toda variable tiene un tipo declarado. A diferencia de C/C++, donde el tamaño de int cambiaba de una computadora a otra, en Java los tipos primitivos tienen tamaño fijo en todas las plataformas: int siempre son 32 bits (4 bytes). Esa es la Tip de portabilidad 4.1.

TipoTamañoRangoValor por defecto (campos)
boolean—true / falsefalse
byte8 bits-128 a 1270
short16 bits-32 768 a 32 7670
int32 bits-2 147 483 648 a 2 147 483 6470
long64 bits-9 223 372 036 854 775 808 a 9 223 372 036 854 775 8070
char16 bitsUnicode '\u0000' a '\uFFFF' (0 a 65 535)'\u0000'

Los literales de texto usan Unicode y los de punto flotante, el estándar IEEE 754 — ambos reconocidos internacionalmente, otra razón de la portabilidad.

Campos vs. variables locales: los campos de una clase (declarados fuera de un método) sí reciben valor por defecto: 0, false, o null en tipos de referencia. Las variables locales (dentro de un método) no: Java exige inicializarlas antes de leerlas (Error común 4.4 de esta misma página).
✓Ya usaste cuatro de los ocho en esta página: int (totales y contadores), double (promedios), boolean (todas las condiciones de los while e if) y char (el 'A' de las letras de calificación). long y byte llegan cuando los números se ponen grandes o pequeños de más.
09 · Ejemplo práctico (opcional)

GUI y gráficos: dibujar con ciclos

Sección 4.14 del libro. Para dibujar en Java hay que conocer el sistema de coordenadas: la esquina superior izquierda de un componente es (0, 0); el eje x crece hacia la derecha, el eje y hacia abajo, y las unidades son píxeles.

La clase PanelDibujo dibuja dos líneas que cruzan el panel; PruebaPanelDibujo la muestra en una ventana:

import java.awt.Graphics;
import javax.swing.JPanel;

public class PanelDibujo extends JPanel
{
    // dibuja una x desde las esquinas del panel
    public void paintComponent( Graphics g )
    {
        // asegura que el panel se muestre correctamente
        super.paintComponent( g );

        int anchura = getWidth();   // anchura total
        int altura = getHeight();   // altura total

        // de la esquina superior izquierda a la inferior derecha
        g.drawLine( 0, 0, anchura, altura );

        // de la esquina inferior izquierda a la superior derecha
        g.drawLine( 0, altura, anchura, 0 );
    }
}
import javax.swing.JFrame;

public class PruebaPanelDibujo
{
    public static void main( String args[] )
    {
        PanelDibujo panel = new PanelDibujo();
        JFrame ventana = new JFrame( "Primer ejemplo de dibujo" );

        ventana.setDefaultCloseOperation( JFrame.EXIT_ON_CLOSE );
        ventana.add( panel );          // agrega el panel a la ventana
        ventana.setSize( 300, 300 );  // anchura x altura en píxeles
        ventana.setVisible( true );
    }
}

extends = herencia

PanelDibujo extends JPanel significa que nuestra clase hereda todo lo que ya hace un JPanel (y le agrega el dibujo). JPanel es la superclase; PanelDibujo, la subclase. El capítulo 9 lo estudia a fondo.

paintComponent

El sistema lo llama automáticamente: al mostrar el panel, al descubrirlo otra vez tras taparlo y al cambiar el tamaño de la ventana. Por eso las líneas se redibujan solas al redimensionar. Su primera instrucción es siempre super.paintComponent( g );.

Aquí es donde los ciclos cobran sentido visual: los ejercicios 4.1 y 4.2 de la sección piden crear diseños de líneas dividiendo la anchura y la altura en 15 pasos y repitiendo g.drawLine(...) con un while que avanza un paso en x y un paso en y en cada iteración. Sin ciclos tendrías que escribir 15 líneas a mano — y si el usuario redimensiona la ventana, a mano otra vez.
10 · Ejemplo práctico (opcional)

Identificar los atributos de una clase (caso ATM)

Sección 4.15 del libro. En el capítulo 3 se identificaron las clases del sistema ATM listando los sustantivos del documento de requerimientos. Ahora toca el paso siguiente: encontrar sus atributos (los datos, que en Java se implementan como campos).

El método

Relee el documento de requerimientos y extrae cada palabra o frase descriptiva que hable de una característica de una clase. En UML se escribe el tipo con mayúscula inicial: Boolean equivale a boolean en Java.

La pregunta de control

¿Qué dato necesita este objeto para hacer su trabajo o para saber en qué estado está? Si la respuesta cambia de objeto a objeto, el atributo va en esa clase.

ClasePalabras/frases del documentoAtributo propuesto
ATM"el usuario es autenticado"usuarioAutenticado : boolean
Cuenta"número de cuenta", "NIP", "saldo"numeroCuenta, nip, saldoDisponible, saldoTotal
Retiro / Deposito"número de cuenta", "monto"numeroCuenta, monto
SolicitudSaldo"número de cuenta"numeroCuenta (no necesita monto)
DispensadorEfectivo"empieza cada día cargado con 500 billetes de $20"conteo de billetes / capacidad
Pantalla, Teclado, BaseDatosBanco…[sin palabras descriptivas]por ahora, ninguno
Un buen ejemplo de "dos atributos para un mismo concepto": una cuenta necesita saldoDisponible (lo que se puede retirar ya) y saldoTotal (lo depositado, incluidos cheques aún sin verificar). Si depositas $50 en una cuenta vacía, saldoTotal pasa a 50 y saldoDisponible sigue en 0 hasta que el banco confirme el sobre. Los atributos modelan el estado real del objeto, no solo "un número que hay".

11 · Función práctica

Dónde viven los ciclos en un programa real

Leer una cantidad desconocida de datos

Calificaciones hasta que el usuario diga basta, líneas de un archivo, registros de una base: casi todo lo que "no sabes cuántos son" es un ciclo con centinela.

Recorrer y acumular

Sumas, promedios, contadores de aprobados/reprobados, ventas del mes, intentos de acceso: total y contador son las dos variables que casi siempre acompañan al ciclo.

Validar hasta que la entrada sea buena

Pedir la edad hasta que esté en rango, el NIP hasta que coincida: while (datoInválido) { pedir otra vez; }.

Menús que no terminan

Un menú de consola que se repite hasta que el usuario elige "Salir" es un ciclo con centinela envolviendo toda la interfaz.

Búsquedas

Recorrer una lista hasta encontrar el elemento o agotar los candidatos; ahí break (visto en la página de condicionales) es el compañero natural del ciclo.

Gráficos y animación

Dibujar 15 líneas, mover un personaje, recalcular una ventana: los ciclos convierten "repetir N veces" en 4 líneas de código (sección 09).

Idea para llevarse: un ciclo es una tarea que se repite hasta que algo cambia. Cuando tu método tenga tres o cuatro instrucciones idénticas seguidas (copiar y pegar), tienes un ciclo esperando escribirse — y casi siempre su nombre es while con un contador o un centinela.
12 · Errores frecuentes

Los tropiezos típicos de este tema

⚠
El ciclo infinito (Error común 4.3). Si en el cuerpo del while no hay ninguna acción que haga que la condición se torne falsa alguna vez, el ciclo nunca termina: el programa se "cuelga". Prueba la pestaña ciclo infinito de arriba y observa cómo total crece sin control mientras la condición sigue siendo true.
⚠
Omitir las llaves del cuerpo (Error común 4.7). Sin { }, el cuerpo del while es solo la instrucción siguiente. En el ejemplo del centinela, si quitas las llaves, el ciclo se queda con total = total + calificacion; y las otras tres líneas —incluida la que relee el dato— quedan fuera: calificacion nunca cambia y el ciclo es infinito. El compilador no dice nada: es un error lógico.
⚠
Un centinela que también es dato válido (Error común 4.6). Si eliges 0 como centinela y alguien saca 0 en el examen, el programa creerá que ya terminaste y dejará de procesar. Elige siempre un valor imposible en los datos permitidos: -1 para calificaciones de 0 a 100.
⚠
Suponer que la división entera redondea (Error común 4.5). 7 / 4 es 1 en Java, no 2: se trunca. Por eso el promedio de 846 / 10 salió 84 y no 84.6. La solución es la conversión explícita (double) total / contador + el especificador %.2f.
⚠
Leer una variable local sin inicializar (Error común 4.4). Es error de compilación en Java. Inicializa totales en 0 y contadores en 0 o 1 — en la declaración o justo antes del ciclo (Tip 4.1).
⚠
++(x + 1) y los espacios en los unarios (Error común 4.9). ++ y -- necesitan una variable como operando, y van pegados a ella: c++, nunca c ++ ni ++ (x + 1).
⚠
Olvidar el if de protección de la división. promedio = total / contador; con contador = 0 (el usuario entró directo con el centinela) lanza ArithmeticException en tiempo de ejecución. El if (contador != 0) de la sección 04 no es decorativo: es lo que evita el choque.
13 · Principio de Pareto

El 20% que produce el 80% de los resultados

Si solo pudieras repasar cinco cosas antes del examen, serían estas:

1 · La forma de todo ciclo while
// fase de inicialización
total = 0; contador = ...;

while ( condicion booleana )
{
    // algo DEBE cambiar
    // para que la condición
    // acabe siendo false
}

// fase de terminación
2 · Las dos familias
// contador (definida):
while ( contador <= 10 ) { ... }

// centinela (indefinida):
lectura = entrada.nextInt();  // ¡antes!
while ( lectura != -1 )
{
   ...; lectura = entrada.nextInt(); // ¡y al final!
}
3 · Inicializar siempre
total = 0;            // totales → 0
contador = 1;         // contadores → 0 o 1

// leer SIN inicializar =
// error de compilación
// (Error común 4.4)
4 · Abreviaturas
total += calificacion;   // = total = total + ...
contador++;             // pre: ++contador;

// c++ en una expresión
// usa ANTES el valor viejo
System.out.println(c++);
5 · El promedio correcto: (double) total / contadorCalif + printf("%.2f", promedio). Sin el cast es división entera (trunca); sin el if (contador != 0) hay ArithmeticException. Estas tres piezas —cast, formato y protección— van juntas en todo cálculo de promedio.
  • while evalúa antes de cada iteración → puede correr 0 veces; el cuerpo va siempre entre llaves.
  • Contador = sabes cuántas vueltas; centinela = no sabes: la primera lectura va fuera del ciclo y se repite al final de cada iteración.
  • Todo ciclo tiene tres fases: inicialización, procesamiento, terminación — y una acción que garantice que termina.
  • total += x, c++ y ++c equivalen a total = total + x y c = c + 1; dentro de una expresión, pre y post no son lo mismo.
  • Los 8 tipos primitivos tienen tamaño fijo (portabilidad): int 32 bits, double 64 bits, char 16 bits, boolean true/false.
14 · Active recall

Pon a prueba lo aprendido

Responde en voz alta antes de abrir cada respuesta. Si dudaste, vuelve a la sección indicada.

1. Con producto = 3, ¿qué valores toma la variable antes de que while (producto <= 100) termine?

3 → 9 → 27 → 81 → 243. Cada iteración triplica el valor: 3·3 = 9, 9·3 = 27, 27·3 = 81, 81·3 = 243. Con 243 la condición <= 100 es falsa, el ciclo termina y producto se queda en 243 (sección 01).

2. En el ciclo con contador, ¿por qué contadorCalif se inicializa en 1 y no en 0?

Porque cuenta "cuál es la calificación que se está pidiendo ahora": la primera que se pide es la número 1. El ciclo corre mientras contadorCalif <= 10, es decir, 10 veces (1, 2, …, 10). Si empezara en 0 y la condición siguiera siendo <= 10, pediría 11 calificaciones. Los totales sí van en 0 (sección 03).

3. Con las entradas 97, 88, 72, -1, ¿qué imprime la versión con centinela y por qué -1 no aparece en la suma?

Total 257, promedio 85.67. El valor se lee al final de cada iteración y antes de reevaluar la condición: al teclear -1, while (calificacion != -1) resulta falsa y el cuerpo no se ejecuta, así que -1 nunca llega a total = total + calificacion. 97 + 88 + 72 = 257; 257 / 3 = 85.666… → %.2f → 85.67 (sección 04).

4. ¿Qué imprime promedio = total / contadorCalif con total = 846 y contador = 10, y qué cambia con (double) total / contadorCalif?

84 (división entera, trunca el .6 — Error común 4.5). Con (double) se crea una copia de punto flotante de total, Java promueve el otro operando y el resultado es 84.6; con printf("%.2f", …) se imprime 84.60 (secciones 03 y 04).

5. ¿Por qué el ciclo de la pestaña "ciclo infinito" nunca termina, aunque el usuario teclea -1 después?

Porque sin llaves el cuerpo es solo total = total + calificacion;. Las líneas que incrementan el contador, piden y releen el dato quedaron fuera del ciclo: calificacion conserva su primer valor (97), la condición != -1 sigue siendo verdadera y el ciclo se repite para siempre (Error común 4.7 + 4.3 — sección 12).

6. Con int c = 5;, ¿qué imprime System.out.println( c++ ); y qué imprime System.out.println( ++c ); si antes se reinicia c = 5?

c++ → imprime 5 y después deja c = 6. ++c → primero deja c = 6 e imprime 6. Por eso la clase Incremento produce 5, 5, 6 y luego 5, 6, 6. Como instrucción suelta, ambas hacen lo mismo: solo cambian dentro de una expresión más grande (sección 07).
