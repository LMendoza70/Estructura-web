01 · Del problema al programa

Algoritmos, seudocódigo y control del programa

Antes de escribir una sola línea de Java hay que entender el problema y planear cómo resolverlo. Un algoritmo es un procedimiento que resuelve un problema en términos de 1) las acciones a ejecutar y 2) el orden en que se ejecutan.

Analogía (Feynman): una receta de cocina es un algoritmo: lista de acciones (romper el huevo, batir, freír) y un orden estricto. Si inviertes el orden "romper el huevo" y "calentar el aceite" misma lista de acciones, el resultado cambia por completo: llegas al trabajo mojado, como el ejecutivo del libro que se viste antes de bañarse.

Especificar el orden en que se ejecutan las instrucciones se llama control del programa. Por defecto, Java ejecuta las instrucciones una tras otra, en el orden en que están escritas: eso es la ejecución secuencial. Cuando la siguiente instrucción a ejecutar no es la que sigue en el texto, estamos ante una transferencia de control — y ahí es donde entran las instrucciones de control de este capítulo.

El seudocódigo: planear sin pelearse con la sintaxis

El seudocódigo es un lenguaje informal, parecido al lenguaje cotidiano, que sirve para desarrollar algoritmos sin preocuparse por los detalles de la sintaxis de Java. No se ejecuta en la computadora: ayuda a "organizar" el programa antes de escribirlo. Un programa en seudocódigo bien hecho se convierte en Java casi por sustitución de líneas.

/* Seudocódigo: determinar si un estudiante aprueba */

Si la calificación del estudiante es mayor o igual a 60
    Imprimir "Aprobado"
De lo contrario
    Imprimir "Reprobado"
✓La sangría del seudocódigo es opcional, pero se recomienda: enfatiza la estructura inherente de los programas estructurados. En Java, la sangría no cambia el programa — pero sí la legibilidad.

Dato de la historia: en la década de los sesenta se identificó a la instrucción goto como culpable de muchos problemas de mantenimiento. Java no tiene goto (sí está reservada la palabra, por lo que no puedes usarla como identificador).

02 · Marco teórico

Solo tres estructuras de control (y dos maneras de combinarlas)

Las investigaciones de Bohm y Jacopini (1966) demostraron que todos los programas pueden escribirse usando únicamente tres estructuras de control. Ese resultado es la base de la programación estructurada: programas más claros, más fáciles de depurar y con menos errores desde el inicio.

1. Secuencia

Las instrucciones se ejecutan una tras otra, en el orden escrito. Es el comportamiento por defecto de Java.

2. Selección

Se elige entre dos o más caminos según el resultado de una condición: if, if...else, switch.

3. Repetición

Se ejecuta un grupo de instrucciones varias veces mientras una condición sea verdadera: while, do...while, for.

Las dos combinaciones posibles

Apilamiento (una instrucción tras otra, punto de salida unido al punto de entrada de la siguiente) y anidamiento (una instrucción de control dentro de otra).

Las palabras if, else, switch, while, do y for son palabras clave: no pueden usarse como nombres de variables o métodos.

03 · Selección simple

La instrucción if

Un programa usa selección para elegir entre cursos de acción. La instrucción if realiza una acción si la condición es verdadera y la omite si es falsa.

/* Seudocódigo */
Si la calificación del estudiante es mayor o igual a 60
    Imprimir "Aprobado"

En Java se escribe casi igual — la condición va siempre entre paréntesis y se evalúa a un valor boolean (true o false):

if ( calificacionEstudiante >= 60 )
    System.out.println( "Aprobado" );

System.out.println( "Fin del programa" );  // se ejecuta SIEMPRE
Con calificacionEstudiante = 75:
Aprobado
Fin del programa

Con calificacionEstudiante = 42:
Fin del programa
Regla clave: si la condición es falsa, no se ejecuta el cuerpo, pero el programa sigue con la instrucción siguiente. El if nunca "detiene" el programa: solo decide si ejecuta o no ese bloque.
Diagrama de actividad UML: el rombo (diamante) es el símbolo de decisión. De él salen dos flechas, cada una con una condición de guardia entre corchetes: [calificacion >= 60] y [calificacion < 60]. Solo una puede ser verdadera, así que el flujo siempre toma exactamente un camino. El círculo relleno es el estado inicial y el círculo doble, el estado final.
⚠Un solo cuerpo: sin llaves, el if controla únicamente la instrucción siguiente. Si quieres varias instrucciones, necesitas un bloque con llaves { } (sección 08).
04 · Selección doble

La instrucción if...else

if solo puede ejecutar o ignorar una acción. if...else permite especificar una acción cuando la condición es verdadera y otra distinta cuando es falsa: siempre se ejecuta exactamente una de las dos.

if ( calificacion >= 60 )
    System.out.println( "Aprobado" );
else
    System.out.println( "Reprobado" );
Diagrama de actividad UML de la instrucción if...else: de la decisión salen dos rutas con condición de guardia y ambas convergen en el estado final.

Buenas prácticas de sangría

  • Utiliza sangría en ambos cuerpos de la instrucción if...else.
  • Si hay varios niveles de sangría, en cada nivel aplica la misma cantidad de espacio adicional (4 espacios en Java).
  • Elige una convención y aplícala de forma consistente en todo el programa.
05 · Azúcar sintáctico

El operador condicional (?:)

Java tiene un único operador ternario: uno que usa tres operandos. Es la forma "exprés" de un if...else que elige uno de dos valores:

// estructura:  condicion ? valor_si_true : valor_si_false

System.out.println( calificacionEstudiante >= 60 ? "Aprobado" : "Reprobado" );

El primer operando (izquierda del ?) es la expresión booleana; el segundo (entre ? y :) es el valor si es verdadera; el tercero (derecha del :) es el valor si es falsa.

int calificacion = 72;
String estado = (calificacion >= 60) ? "Aprobado" : "Reprobado";

System.out.println( estado );   // Salida: Aprobado
✓Cuándo usarlo: cuando sustituye a un if...else simple que solo selecciona uno de dos valores. Su precedencia es baja, así que conviene encerrar toda la expresión entre paréntesis como en el ejemplo.
⚠Cuándo NO usarlo: las expresiones condicionales son más difíciles de leer que un if...else con nombre propio. Si tienes varias condiciones, varios efectos secundarios o líneas anidadas de ?...:..., escribe el if...else normal.
06 · Selección múltiple con if

La cadena else if: rangos y varios casos

Para evaluar varios casos se colocan instrucciones if...else dentro de otras. Tradicionalmente se escribe "escalera", y la mayoría de los programadores prefieren la forma else if compacta:

int calificacionEstudiante = 85;

if ( calificacionEstudiante >= 90 )
    System.out.println( "A" );
else if ( calificacionEstudiante >= 80 )
    System.out.println( "B" );
else if ( calificacionEstudiante >= 70 )
    System.out.println( "C" );
else if ( calificacionEstudiante >= 60 )
    System.out.println( "D" );
else
    System.out.println( "F" );
Salida:
B
Por qué imprime "B" y no "A": con 85, las cuatro primeras condiciones serían relevantes… pero solo se evalúan hasta la primera que sea verdadera. La cadena se corta: calificacion >= 90 es false, luego >= 80 es true → se ejecuta el "B" y ya no se evalúa nada más. Prueba 95 en la mesa de decisiones de arriba.

El orden importa: trampa de los rangos

Cuando las condiciones se solapan, el orden en que las escribes decide el resultado:

Orden incorrecto
if ( nota >= 60 )
    letra = "D";
else if ( nota >= 90 )
    letra = "A";   // ¡inalcanzable!
// una nota de 95 cae en la PRIMERA
// rama y nunca llega a "A"
Orden correcto
if ( nota >= 90 )
    letra = "A";
else if ( nota >= 60 )
    letra = "D";
// de mayor a menor: el rango más
// específico se evalúa primero
✓Regla práctica: en cadenas de rangos, ordena las condiciones de la más restrictiva a la más amplia (de mayor a menor). Y recuerda que else siempre es la red de seguridad: captura todo lo que ninguna condición anterior capturó.
07 · El error clásico

El problema del else suelto (dangling else)

El compilador de Java asocia cada else con el if que le precede inmediatamente, a menos que las llaves { } digan lo contrario. Esa regla produce el famoso problema del else suelto.

Lo que parece decir
if ( x > 5 )
    if ( y > 5 )
        System.out.println(
            "x e y son > 5" );
else                          // ¿del primer if?
    System.out.println(
        "x es <= 5" );
Lo que hace el compilador
if ( x > 5 )
    if ( y > 5 )
        System.out.println(
            "x e y son > 5" );
    else                      // ¡del if
        System.out.println(   // interior!
            "x es <= 5" );

Veamos las consecuencias con la mesa de decisiones (pestaña "else suelto"): si x = 7 y y = 3, el programa imprime "x es <= 5"… aunque x NO sea menor o igual a 5. Y si x = 3, el programa no imprime nada: el else pertenece al if interior, que nunca se ejecutó porque el if exterior era falso.

La solución: di exactamente a qué if pertenece el else

if ( x > 5 )
{
    if ( y > 5 )
        System.out.println( "x e y son > 5" );
}
else
    System.out.println( "x es <= 5" );
Las llaves le dicen al compilador que el segundo if pertenece al cuerpo del primero, y que el else se asocia con el if exterior. En la mesa de decisiones compara la pestaña "else suelto" con este código: el resultado de x = 7, y = 3 cambia.
✓Hoy en día la mayoría de los guías de estilo recomiendan usar llaves siempre en todo if y else, aunque el cuerpo tenga una sola línea: elimina de raíz esta clase de errores.
08 · Bloques, llaves y puntos y coma

Cómo agrupar varias instrucciones (y el punto y coma que arruina todo)

El if espera una sola instrucción en su cuerpo. Para incluir varias, enciérralas entre llaves: a ese conjunto de instrucciones se le llama bloque, y puede aparecer en cualquier lugar donde quepa una instrucción individual.

if ( calificacion >= 60 )
    System.out.println( "Aprobado" );
else
{
    System.out.println( "Reprobado." );
    System.out.println( "Debe tomar este curso otra vez." );
}
Con calificacion = 45:
Reprobado.
Debe tomar este curso otra vez.
⚠Sin las llaves del else, la segunda línea quedaría fuerza del cuerpo y se ejecutaría siempre, incluso cuando el estudiante aprueba. Este es un error lógico: el compilador no se queja (la sintaxis es válida), pero el programa produce resultados incorrectos.

El punto y coma que no debería estar ahí

// ❌ ERROR LÓGICO: ese ; convierte el cuerpo del if
//    en una instrucción VACÍA
if ( calificacion >= 60 );
    System.out.println( "Aprobado" );  // se imprime SIEMPRE
Error común 4.2 del libro: un ; después de la condición produce un error lógico en el if simple (el cuerpo queda vacío y la instrucción siguiente se ejecuta sin condición) y un error de compilación cuando el if...else tiene una instrucción en su cuerpo (habría dos "cuerpos").
  • Usa llaves { } siempre, incluso con una sola instrucción: es la defensa contra los errores lógicos silenciosos.
  • Si escribes las llaves de apertura y cierre antes del contenido, no se te olvidará cerrar el bloque.
  • Un error de sintaxis lo atrapa el compilador; un error lógico solo lo descubre el usuario en tiempo de ejecución.
  • La instrucción vacía ; es válida en Java, pero casi nunca es lo que querías escribir.
09 · Selección múltiple

La instrucción switch

Cuando hay que elegir entre muchos valores exactos de una misma variable, encadenar if...else if se vuelve tedioso. La instrucción switch realiza una de varias acciones distintas según el valor de una expresión entera o de carácter.

Expresión de control

Lo que va entre paréntesis después de switch. Se evalúa una sola vez y debe ser byte, short, int, char o String — nunca long.

case

Etiquetas con constantes (case 8:, case 'A':, case "lunes":). Si la expresión coincide, se ejecutan las instrucciones de ese case.

break

Sale inmediatamente del switch. Sin ella, la ejecución continúa con el case siguiente: es el famoso fall-through (o "se pasa de largo").

default

Se ejecuta si ningún case coincide. Es la red de seguridad: conviene incluirlo siempre.

int diaSemana = 3;

switch ( diaSemana )          // expresión de control
{
    case 1:
        System.out.println( "Lunes" );
        break;                  // sale del switch
    case 2:
        System.out.println( "Martes" );
        break;
    case 3:
        System.out.println( "Miércoles" );
        break;
    default:
        System.out.println( "Valor no válido" );
        break;
}

System.out.println( "Sigue el resto del programa" );
Salida con diaSemana = 3:
Miércoles
Sigue el resto del programa

Varios valores, una misma acción (case consecutivos)

Java no evalúa rangos: cada valor debe listarse en su propio case. Si dos o más case van seguidos sin instrucciones entre ellos, comparten las mismas líneas:

switch ( calificacion / 10 )   // 85 / 10 = 8 (división entera)
{
    case 10:                    // 100, 99, 98 ... 90
    case 9:
        System.out.println( "A" );
        break;
    case 8:
        System.out.println( "B" );
        break;
    default:
        System.out.println( "Otro" );
}
La astucia de calificacion / 10: la división entera trunca los decimales, así que cualquier nota de 90 a 99 se convierte en 9 (y 100 queda en 10). Ese truco convierte un rango en un valor exacto que el switch sí sabe comparar.
⚠Error común 5.7 del libro: olvidar un break donde hace falta. Sin él, los case "se pasan" al siguiente y se ejecutan acciones que no tocaban. Prueba la pestaña "switch" de la mesa de decisiones con break desactivado y calificación 85: verás imprimir B, C, D y F en la misma corrida.

10 · Caso completo

LibroCalificaciones: switch en un programa real

Este es el ejemplo con el que el libro desarrolla la clase LibroCalificaciones: lee un número arbitrario de calificaciones, calcula el promedio y, gracias a un switch, cuenta cuántos estudiantes obtuvieron A, B, C, D o F.

Parte 1 — los datos y la entrada. Observa las variables de instancia (se inicializan en 0 por defecto) y el método que recibe la entrada con Scanner:

import java.util.Scanner;   // el programa usa la clase Scanner

public class LibroCalificaciones
{
    private String nombreDelCurso;  // curso que representa este objeto
    private int total;              // suma de las calificaciones
    private int contadorCalif;      // número de calificaciones leídas
    private int aCuenta;            // cuenta de calificaciones A
    private int bCuenta;            // cuenta de calificaciones B
    private int cCuenta;            // cuenta de calificaciones C
    private int dCuenta;            // cuenta de calificaciones D
    private int fCuenta;            // cuenta de calificaciones F

    // el constructor solo establece el nombre del curso;
    // las variables int restantes quedan en 0 por defecto
    public LibroCalificaciones( String nombre )
    {
        nombreDelCurso = nombre;
    }

    public void establecerNombreDelCurso( String nombre )
    {
        nombreDelCurso = nombre;
    }

    public String obtenerNombreDelCurso()
    {
        return nombreDelCurso;
    }

    // muestra el mensaje de bienvenida
    public void mostrarMensaje()
    {
        System.out.printf( "Bienvenido al libro de calificaciones para\n%s!\n\n",
            obtenerNombreDelCurso() );
    }

    // lee un número arbitrario de calificaciones del usuario
    public void introducirCalif()
    {
        Scanner entrada = new Scanner( System.in );
        int calificacion;   // calificación introducida por el usuario

        System.out.printf( "%s\n%s\n   %s\n   %s\n",
            "Escriba las calificaciones enteras en el rango de 0 a 100.",
            "Escriba el indicador de fin de archivo para terminar la entrada:",
            "En UNIX/Linux/Mac OS X escriba <ctrl> d y después oprima Intro",
            "En Windows escriba <ctrl> z y después oprima Intro" );

        while ( entrada.hasNext() )   // repetición controlada por centinela
        {
            calificacion = entrada.nextInt();  // lee una calificación
            total += calificacion;             // la suma a total
            ++contadorCalif;                   // cuenta la calificación leída
            incrementarContadorCalifLetra( calificacion );
        }
    }
    // suma 1 al contador apropiado para la calificación indicada.
    // es un método utilitario: solo lo llama introducirCalif().
    private void incrementarContadorCalifLetra( int calificacion )
    {
        switch ( calificacion / 10 )   // expresión de control
        {
            case 10:  // calificación entre 90 y 100
            case 9:   // (ambos case comparten el mismo cuerpo)
                ++aCuenta;
                break;   // necesaria para salir del switch
            case 8:   // calificación entre 80 y 89
                ++bCuenta;
                break;
            case 7:   // calificación entre 70 y 79
                ++cCuenta;
                break;
            case 6:   // calificación entre 60 y 69
                ++dCuenta;
                break;
            default:  // cualquier otra: calificación < 60
                ++fCuenta;
                break;   // opcional: es el último
        }
    }

    // imprime el reporte con base en las calificaciones leídas
    public void mostrarReporteCalif()
    {
        System.out.println( "\nReporte de calificaciones:" );

        if ( contadorCalif != 0 )   // evita la división entre cero
        {
            double promedio = (double) total / contadorCalif;

            System.out.printf( "El total de las %d calificaciones introducidas es %d\n",
                contadorCalif, total );
            System.out.printf( "El promedio de la clase es %.2f\n", promedio );
            System.out.printf( "%s\n%s%d\n%s%d\n%s%d\n%s%d\n%s%d\n",
                "Numero de estudiantes que recibieron cada calificacion:",
                "A: ", aCuenta,
                "B: ", bCuenta,
                "C: ", cCuenta,
                "D: ", dCuenta,
                "F: ", fCuenta );
        }
        else
        {
            System.out.println( "No se introdujeron calificaciones" );
        }
    }
}

Parte 2 — la clase que lo pone en marcha. Observa que PruebaLibroCalificaciones nunca llama a incrementarContadorCalifLetra: es un método privado que solo se invoca desde dentro de introducirCalif().

11 · Alterar el flujo

Las instrucciones break y continue

Además de selección y repetición, Java tiene dos instrucciones que alteran el flujo de control:

break

Dentro de while, do...while, for o switch, provoca la salida inmediata de esa instrucción. La ejecución continúa en la primera línea después de ella.

continue

Dentro de un ciclo, salta al final de la iteración actual y pasa a la siguiente sin ejecutar el resto del cuerpo. No sale del ciclo: lo salta una vez.

Java también tiene break y continue etiquetados para instrucciones anidadas (se tratan en el apéndice N del libro). Aquí vemos los usos básicos.

// Fig. 5.12 — salir de un ciclo for con break
public class PruebaBreak
{
    public static void main( String args[] )
    {
        int cuenta;   // la variable de control se usa también al salir

        for ( cuenta = 1; cuenta <= 10; cuenta++ )   // itera 10 veces
        {
            if ( cuenta == 5 )   // si cuenta es 5,
                break;             // termina el ciclo

            System.out.printf( "%d ", cuenta );
        }

        System.out.printf( "\nSalio del ciclo en cuenta = %d\n", cuenta );
    }
}
1 2 3 4
Salio del ciclo en cuenta = 5
Lectura del ejemplo: el ciclo estaba preparado para llegar a 10, pero cuando cuenta valió 5 el break sacó al programa del for. Por eso la última línea imprime 5 y no 11: la variable de control se "congela" en el valor que provocó la salida.
⚠Nota: break no tiene ningún efecto dentro de un if. Su dominio son los ciclos y el switch. Si escribes if (x) break; dentro de un ciclo, el break actúa sobre el ciclo, no sobre el if.
✓Cuándo conviene: break es ideal para "escapar" de un ciclo cuando ya se encontró lo que se buscaba (una búsqueda, una validación de datos). continue sirve para saltar elementos que no interesan en la iteración actual. Pero si el programa se vuelve difícil de seguir con muchas sentencias de salto, casi siempre existe una versión más clara con condiciones bien planteadas.

13 · Errores frecuentes

Los tropiezos típicos de este tema

⚠
= en lugar de == en la condición. En Java, = es asignación y == es igualdad. La expresión if (calificacion = 60) compila (asigna 60 a la variable y el valor 60 se convierte en true), así que el error solo se nota en la lógica del programa. Casi todos los compiladores lo advierten como warning: léelo.
⚠
El ; tras la condición del if. if (x > 5); deja el cuerpo vacío y la instrucción siguiente se ejecuta siempre (error lógico silencioso). En un if...else bien formado produce un error de compilación.
⚠
Escribir rangos como en matemáticas. 18 <= edad <= 65 es error de compilación en Java: primero compara 18 <= edad (devuelve un booleano) y luego intenta comparar ese booleano con 65. La forma correcta es edad >= 18 && edad <= 65.
⚠
Condiciones redundantes. if (x == true) o if (x != false) son verbosas; if (x) basta. Del mismo modo, if (x != false) no es lo mismo que if (x) cuando x es un número: solo los valores 1 y 0 son equivalentes, no 1 y cualquier distinto de 0.
⚠
Olvidar las llaves en el cuerpo. Si el if debe abarcar dos instrucciones y no le pones { }, la segunda se ejecuta sin condición. El programa compila y falla lógicamente — el peor tipo de error.
⚠
switch sin break. Produce fall-through: se ejecutan los case siguientes aunque no coincidan. También olvidar que las etiquetas deben ser constantes (no variables) y que dos case con el mismo valor son un error de compilación.
⚠
Comparar texto con ==. En switch (cadena) Java compara bien, pero en código normal if (nombre == "Ana") compara referencias, no el contenido. Para String usa nombre.equals("Ana").
⚠
El default que falta. Si la entrada del usuario es inesperada y no hay default, el programa no hace nada y da la sensación de que "se quedó colgado". Inclúyelo siempre, aunque solo sea para mostrar un mensaje de error.
14 · Principio de Pareto

El 20% que produce el 80% de los resultados

Si solo pudieras repasar cinco cosas antes del examen, serían estas:

1 · La forma de toda decisión
if ( condicion booleana )
    instruccion;
else
    instruccion;

// la condición SIEMPRE entre ( )
// y SIEMPRE de tipo boolean
2 · El operador ternario
condicion ? valor_si_true
          : valor_si_false

// atajo de if...else que
// solo elige uno de dos valores
3 · La cadena else if
if      ( nota >= 90 ) letra = "A";
else if ( nota >= 80 ) letra = "B";
else                letra = "F";
// se evalúa en orden y se corta
// en la primera condición cierta
4 · Anatomía del switch
switch ( expresion ) {
   case cte: ...; break;
   default: ...;  break;
}
// constantes + break + default
5 · Los tres defectos que más se repiten: = en vez de ==, el ; vacío después del if y el break olvidado en el switch. Los tres compilan (o casi) y los tres arruinan la lógica del programa.
  • if → selección simple; if...else → doble; cadena else if → múltiple con rangos.
  • switch → múltiple con valores exactos; el truco valor / 10 convierte rangos en casos.
  • Java asocia cada else con el if más cercano: usa llaves para dejarlo claro.
  • break sale; continue salta a la siguiente iteración; ninguno actúa dentro de un if aislado.
  • Error de sintaxis lo detecta el compilador; error lógico lo detecta quien usa el programa.
15 · Active recall

Pon a prueba lo aprendido

Responde en voz alta antes de abrir cada respuesta. Si dudaste, vuelve a la sección indicada.

1. Con calificacion = 72, ¿qué imprime la cadena else if de la sección 06?

"C". Las condiciones se evalúan en orden: >= 90 es falsa, >= 80 es falsa, >= 70 es verdadera → se imprime "C" y la cadena se corta. Las ramas siguientes ya no se evalúan.

2. ¿Qué pasa en if (x > 5); con x = 3?

El ; convierte el cuerpo en una instrucción vacía, así que siempre se ejecuta nada y la instrucción siguiente corre sin ninguna condición. Con x = 3 se imprime igual: es un error lógico que el compilador no detecta.

3. En switch (calificacion / 10) con calificacion = 85, ¿qué se imprime si ningún break está presente?

B, C, D y F. La entrada cae en case 8 y, al faltar los break, la ejecución se desliza (fall-through) por todos los case posteriores, incluido default. Prueba la pestaña switch con el checkbox "break activo" apagado.

4. ¿Cuál es la forma correcta de verificar que una edad está entre 18 y 65 años?

edad >= 18 && edad <= 65. La expresión 18 <= edad <= 65 es un error de compilación en Java: primero obtiene un booleano y luego intenta compararlo con 65.

5. Si una variable int tiene valor 95, ¿qué expresión permite usarla como etiqueta de un switch para descartar los decimales?

valor / 10 → 95 / 10 = 9 (división entera, trunca). Así cualquier nota de 90 a 99 se vuelve el caso 9, y 100 produce 10, por eso se listan case 10: y case 9: juntos.
