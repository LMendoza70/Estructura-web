Colas: el primero en llegar es el primero en salir

Una cola es una fila para comprar boletos: quien llega se forma al final, y quien es atendido siempre sale por el frente. Nadie se salta la fila.

← sale por aquí (frente)            entra por aquí (final) →
Cola vacía.

FIFO: First In, First Out — el orden de salida es el mismo orden en que fueron llegando.

01 · Concepto de colas

¿Qué es una cola?

Una cola (queue) es una estructura de datos dinámica que organiza sus elementos bajo la política FIFO (First In, First Out): el primer elemento que entra es el primero en salir. A diferencia de la pila, una cola tiene dos puntos de acceso: se agrega por un extremo (el final) y se retira por el otro (el frente).

Analogía: la fila para comprar boletos en el cine. Cada persona que llega se forma al final de la fila. La taquilla siempre atiende a quien está hasta el frente. Nadie puede "colarse" a media fila ni ser atendido antes que quienes llegaron primero. Ese orden estricto de llegada-salida es exactamente el de una cola.
02 · Componentes

Las piezas de una cola

frente (front)

Referencia al primer elemento, el siguiente que será retirado. Es el punto de salida.

final (rear / tail)

Referencia al último elemento agregado. Es el punto de entrada para los nuevos elementos.

elementos

El conjunto de datos almacenados en el orden exacto en que fueron llegando.

estructura interna

Puede implementarse con un arreglo circular o, de forma dinámica, con nodos enlazados que mantienen referencias tanto al frente como al final.

03 · Operaciones

Lo que se le puede hacer a una cola

enqueue(valor)

Agrega un nuevo elemento al final de la cola.

dequeue()

Retira y devuelve el elemento que está en el frente. El siguiente elemento pasa a ser el nuevo frente.

peek() / front()

Devuelve el valor del frente sin retirarlo de la cola.

isEmpty()

Indica si la cola no tiene elementos. Debe consultarse antes de dequeue() o peek().

public class Cola<T> {

    private class Nodo {
        T dato;
        Nodo siguiente;
        Nodo(T dato) { this.dato = dato; }
    }

    private Nodo frente;
    private Nodo final_;
    private int tamano = 0;

    public void enqueue(T valor) {
        Nodo nuevo = new Nodo(valor);
        if (isEmpty()) {
            frente = nuevo;        // primer elemento: es a la vez frente y final
        } else {
            final_.siguiente = nuevo;   // se engancha después del último actual
        }
        final_ = nuevo;
        tamano++;
    }

    public T dequeue() {
        if (isEmpty()) {
            throw new IllegalStateException("La cola está vacía");
        }
        T valor = frente.dato;
        frente = frente.siguiente;   // el segundo elemento pasa a ser el nuevo frente
        if (frente == null) {
            final_ = null;         // la cola quedó vacía: también se limpia el final
        }
        tamano--;
        return valor;
    }

    public T peek() {
        if (isEmpty()) {
            throw new IllegalStateException("La cola está vacía");
        }
        return frente.dato;
    }

    public boolean isEmpty() {
        return frente == null;
    }

    public int size() {
        return tamano;
    }
}

Nótese la diferencia clave con la pila: enqueue() agrega por el final, pero dequeue() retira por el frente — son dos extremos distintos, no el mismo.

04 · Función práctica

Dónde se usan las colas para resolver problemas reales

Cola de impresión

Los documentos se imprimen en el mismo orden en que se enviaron a la impresora.

Atención al cliente / call center

Las llamadas o tickets de soporte se atienden en el orden en que llegaron.

Planificación de procesos (CPU)

El sistema operativo puede repartir tiempo de procesador entre tareas en el orden en que fueron encoladas.

Recorrido BFS en grafos y árboles

La búsqueda en anchura (Breadth-First Search) usa una cola para visitar los nodos nivel por nivel.

Buffers de datos

Streaming de video o audio: los datos se encolan al llegar y se procesan en el mismo orden de llegada.

Simulación de filas reales

Modelar bancos, cajas de supermercado o cualquier sistema de atención por turnos.

06 · Errores frecuentes

Lo que suele fallar

⚠
Hacer dequeue() o peek() sobre una cola vacía: sin verificar isEmpty() antes, se produce una excepción o un comportamiento indefinido.
⚠
Olvidar actualizar final_ cuando la cola queda vacía: si tras un dequeue() el frente queda en null pero el final no se limpia, el siguiente enqueue() puede dejar la estructura inconsistente.
⚠
Confundir cola con pila: aplicar lógica LIFO donde el problema exige FIFO (o viceversa) invierte por completo el orden en que se procesan los elementos.
07 · Principio de Pareto

El 20% de reglas que explica el 80% de las colas

  • Se agrega por el final y se retira por el frente: son dos extremos distintos.
  • FIFO: el orden de salida siempre respeta el orden de llegada.
  • enqueue() agrega al final; dequeue() quita y devuelve el frente; peek() solo consulta el frente.
  • Siempre valida isEmpty() antes de dequeue() o peek().
  • Si el problema exige procesar en el mismo orden en que van llegando los elementos, casi siempre hay una cola detrás.
08 · Active recall

Ponte a prueba (haz clic en cada pregunta)

1. ¿Qué significa que una cola sea FIFO?
Que el primer elemento en entrar es el primero en salir: el orden de salida respeta exactamente el orden de llegada.
2. ¿Por qué una cola necesita dos referencias (frente y final) y una pila solo necesita una (tope)?
Porque en la cola las operaciones ocurren en extremos distintos: se agrega por el final y se retira por el frente. En la pila, tanto agregar como retirar ocurren en el mismo extremo (el tope), por lo que una sola referencia basta.
3. Si encolas A, B y C en ese orden, ¿en qué orden saldrán al hacer dequeue() tres veces?
A, luego B, luego C — el mismo orden en que entraron, porque la cola es FIFO.
4. Menciona un algoritmo clásico que dependa de una cola para funcionar correctamente.
La búsqueda en anchura (BFS) en grafos o árboles, que usa una cola para visitar los nodos nivel por nivel, en el orden en que se van descubriendo.
