Tipos de Datos Abstractos

5 ejercicios

Diseñar una clase que oculte su implementación y exponga solo un contrato de operaciones válidas.

Nivel 1

Contador de visitas de una página

Caso de uso

Un sitio web necesita registrar cuántas veces se ha visitado una página, sin que ningún otro módulo del sistema pueda modificar ese número directamente, solo incrementarlo o consultarlo.

Requisitos
  • Atributo visitas privado, inicia en 0.
  • Método registrarVisita() incrementa en 1.
  • Método obtenerVisitas() consulta sin modificar.
Nivel 2

TDA Fracción

Caso de uso

Una calculadora escolar necesita representar fracciones (numerador/denominador) y sumarlas entre sí, garantizando que el denominador nunca pueda quedar en cero.

Requisitos
  • Atributos numerador y denominador privados.
  • Constructor que rechace denominador 0.
  • Método sumar(Fraccion otra) que devuelva una nueva fracción.
Nivel 3

Agenda de citas de un consultorio

Caso de uso

Un consultorio dental necesita agendar citas por hora, evitando que se registren dos citas que se traslapen en el mismo horario.

Requisitos
  • Método agendar(horaInicio, horaFin) que valide traslape contra citas ya guardadas.
  • Método cancelar(horaInicio).
  • Estado interno de citas no accesible directamente desde fuera de la clase.
Nivel 4

Inventario de un producto

Caso de uso

Una tienda necesita controlar el stock de un producto: debe poder surtir y vender unidades, pero nunca debe permitirse que el stock quede en negativo, y debe poder consultarse si el stock está por debajo de un umbral de reorden.

Requisitos
  • Métodos surtir(cantidad) y vender(cantidad) con validación.
  • Método necesitaReabastecimiento() según un umbral configurable.
  • Excepción propia si se intenta vender más de lo disponible.
Nivel 5

Cuenta bancaria con historial de movimientos

Caso de uso

Extiende la CuentaBancaria vista en clase para que registre internamente cada depósito y retiro con fecha, y permita consultar el historial completo sin que quien lo consulta pueda alterarlo.

Requisitos
  • Lista interna privada de movimientos.
  • obtenerHistorial() debe devolver una copia, nunca la referencia interna.
  • Cada movimiento registra tipo, monto y saldo resultante.

Recursividad

5 ejercicios

Identificar el caso base y el caso recursivo, y trazar la pila de llamadas resultante.

Nivel 1

Potencia de un número

Caso de uso

Una calculadora científica necesita calcular base^exponente usando únicamente multiplicaciones sucesivas, sin usar bucles.

Requisitos
  • Método potencia(base, exponente).
  • Caso base: exponente 0 devuelve 1.
  • Caso recursivo: base * potencia(base, exponente-1).
Nivel 2

Suma de dígitos de un número

Caso de uso

Un sistema de validación de tarjetas necesita sumar todos los dígitos de un número (por ejemplo, para un dígito verificador) sin convertirlo primero a texto.

Requisitos
  • Método sumaDigitos(int numero).
  • Usa numero % 10 y numero / 10 en cada llamada.
  • Caso base: número igual a 0.
Nivel 3

Verificar si una palabra es palíndromo

Caso de uso

Un juego de palabras necesita detectar automáticamente si una palabra ingresada por el usuario se lee igual al derecho y al revés.

Requisitos
  • Método esPalindromo(String texto).
  • Compara primer y último carácter, y recursa sobre el resto.
  • Caso base: cadena de longitud 0 o 1.
Nivel 4

Invertir una lista enlazada

Caso de uso

Un reproductor de música quiere ofrecer la opción "reproducir en orden inverso" sobre su lista de canciones enlazada, sin crear una lista nueva desde cero.

Requisitos
  • Método recursivo que reciba la cabeza de la lista y devuelva la nueva cabeza invertida.
  • Reutiliza los mismos nodos, solo reconecta referencias.
  • Caso base: nodo actual es null o es el último.
Nivel 5

Torres de Hanói

Caso de uso

Un juego educativo de lógica pide mover una torre de discos de un poste a otro, respetando que nunca un disco más grande quede sobre uno más pequeño, usando un poste auxiliar.

Requisitos
  • Método hanoi(n, origen, destino, auxiliar).
  • Imprime cada movimiento individual de disco.
  • Caso base: un solo disco (n == 1).

Arreglos

5 ejercicios

Declarar, crear y manipular arreglos, incluyendo recorridos y operaciones in-place.

Nivel 1

Máximo y mínimo en calificaciones

Caso de uso

Un profesor capturó las calificaciones de un grupo en un arreglo y necesita saber cuál fue la calificación más alta y la más baja del examen.

Requisitos
  • Recorrer el arreglo una sola vez.
  • Devolver ambos valores (por ejemplo, en un arreglo de tamaño 2).
Nivel 2

Promedio de ventas diarias

Caso de uso

Una tienda registró sus ventas de los últimos 30 días en un arreglo y quiere saber cuál fue el promedio diario de ventas del mes.

Requisitos
  • Sumar todos los elementos con un for.
  • Dividir entre arreglo.length.
Nivel 3

Conteo de lecturas pares e impares de un sensor

Caso de uso

Un sensor de temperatura registra lecturas enteras a lo largo del día; se necesita reportar cuántas lecturas fueron pares y cuántas impares.

Requisitos
  • Dos contadores acumulados en un solo recorrido.
  • Uso del operador módulo (%).
Nivel 4

Invertir el orden de turnos sin arreglo auxiliar

Caso de uso

Una clínica quiere invertir el orden de atención de su lista de turnos del día (el último paciente pasa primero), modificando el mismo arreglo en memoria, sin crear uno nuevo.

Requisitos
  • Intercambiar elementos de los extremos hacia el centro (dos punteros).
  • No usar un segundo arreglo del mismo tamaño.
Nivel 5

Matriz de asistencia semanal

Caso de uso

Un maestro quiere llevar el control de asistencia de sus alumnos durante la semana (5 días) usando una matriz, y al final calcular cuántos días asistió cada alumno y cuántos alumnos asistieron cada día.

Requisitos
  • Arreglo bidimensional boolean[][] asistencia (alumnos x días).
  • Totales por fila (por alumno) y por columna (por día).

Clases parametrizadas y genéricos

5 ejercicios

Diseñar clases y métodos que funcionen para distintos tipos sin duplicar código.

Nivel 1

Registro con marca de tiempo

Caso de uso

Un sistema de monitoreo necesita envolver cualquier tipo de dato (temperatura, presión, texto de estado) junto con el momento exacto en que fue capturado.

Requisitos
  • Clase Registro<T> con valor y marcaTiempo.
  • Instanciar con al menos dos tipos distintos.
Nivel 2

Resultado de una operación (éxito/error)

Caso de uso

Un módulo de validación de formularios necesita devolver, para cualquier tipo de dato validado, si la operación tuvo éxito y el valor resultante, o un mensaje de error si falló.

Requisitos
  • Clase Resultado<T> con exito, valor y mensajeError.
  • Dos constructores o métodos estáticos: uno para éxito, otro para error.
Nivel 3

Elemento más repetido de un arreglo genérico

Caso de uso

Una encuesta guarda las respuestas de opción múltiple en un arreglo y se necesita un método reutilizable que funcione tanto para respuestas de texto como para calificaciones numéricas, y devuelva la que más se repitió.

Requisitos
  • Método genérico <T> T masRepetido(T[] datos).
  • Probarlo con String[] e Integer[].
Nivel 4

Par ordenado comparable por clave

Caso de uso

Un sistema de rankings necesita ordenar pares (nombre del jugador, puntaje) por su clave, permitiendo reutilizar la misma clase para rankings de distintos tipos de identificador (nombre, código de jugador).

Requisitos
  • Clase ParOrdenado<K extends Comparable<K>, V>.
  • Implementa comparación basada solo en K.
Nivel 5

Caché con capacidad máxima

Caso de uso

Una aplicación necesita una caché reutilizable (para distintos tipos de clave y valor) que guarde un número limitado de resultados, descartando el más antiguo cuando se llena.

Requisitos
  • Clase Cache<K, V> con capacidad fija en el constructor.
  • Método put(K,V) que descarte la entrada más antigua si ya está llena.

Listas enlazadas

5 ejercicios

Aplicar listas simples, dobles y circulares según el problema lo requiera.

Nivel 1

Lista de tareas pendientes

Caso de uso

Una aplicación de productividad necesita agregar tareas al final de una lista y mostrarlas todas en el orden en que se capturaron.

Requisitos
  • Lista simple con insertarFinal(tarea).
  • Método mostrarTodas().
Nivel 2

Eliminar una tarea específica

Caso de uso

Sobre la misma lista de tareas, el usuario marca una tarea como completada y esta debe eliminarse de la lista, sin importar en qué posición se encuentre.

Requisitos
  • Método eliminar(valor) que reconecte los nodos vecinos.
  • Manejar el caso de eliminar la cabeza.
Nivel 3

Historial de navegación de un navegador

Caso de uso

Un navegador web necesita permitir avanzar y retroceder entre las páginas visitadas, recordando tanto la página anterior como la siguiente desde cualquier punto del historial.

Requisitos
  • Lista doblemente enlazada.
  • Métodos visitar(url), atras(), adelante().
Nivel 4

Turnos rotativos de un juego de mesa

Caso de uso

Un juego de mesa para 5 jugadores necesita repartir el turno en orden y, al llegar al último jugador, volver automáticamente al primero, indefinidamente.

Requisitos
  • Lista circular simple con 5 nodos.
  • Método siguienteTurno() que avance y regrese al inicio tras el último.
Nivel 5

Fusionar dos listas ordenadas

Caso de uso

Dos sucursales de una tienda enviaron cada una su lista de productos más vendidos, ya ordenada por código de producto, y se necesita combinarlas en una sola lista ordenada para el reporte general.

Requisitos
  • Método fusionar(lista1, lista2) que devuelva una sola lista simple ordenada.
  • No debe volver a ordenar todo desde cero: aprovechar que ambas ya vienen ordenadas.

Pilas

5 ejercicios

Reconocer problemas que requieren procesar "lo último agregado, primero".

Nivel 1

Paréntesis balanceados

Caso de uso

Un editor de código necesita marcar en rojo una línea si los paréntesis, corchetes o llaves que contiene no están correctamente balanceados.

Requisitos
  • Apilar cada símbolo de apertura.
  • Al encontrar un cierre, hacer pop() y comparar.
Nivel 2

Función deshacer de un editor de texto

Caso de uso

Un editor de texto simple necesita permitir deshacer la última acción del usuario (escribir, borrar, pegar), en el orden inverso a como se realizaron.

Requisitos
  • Pila de acciones registradas.
  • Método deshacer() que haga pop() y revierta esa acción.
Nivel 3

Evaluar una expresión postfija

Caso de uso

Una calculadora científica interna representa las operaciones en notación postfija (por ejemplo, 3 4 +) y necesita evaluarlas correctamente.

Requisitos
  • Apilar operandos; al leer un operador, desapilar dos y apilar el resultado.
  • El resultado final queda como único elemento de la pila.
Nivel 4

Convertir una expresión infija a postfija

Caso de uso

Antes de poder evaluar expresiones matemáticas escritas de forma normal (infija), el sistema necesita convertirlas primero a notación postfija respetando la precedencia de operadores.

Requisitos
  • Pila auxiliar de operadores.
  • Reglas de precedencia entre + - * /.
Nivel 5

Navegación adelante/atrás de un navegador

Caso de uso

El botón "atrás" y "adelante" de un navegador web debe funcionar aunque el usuario visite nuevas páginas después de haber retrocedido, descartando el historial de "adelante" que ya no aplica.

Requisitos
  • Dos pilas: atras y adelante.
  • Visitar una nueva página limpia la pila adelante.

Colas

5 ejercicios

Reconocer problemas que exigen procesar en el mismo orden en que llegan los elementos.

Nivel 1

Fila de atención en una caja de banco

Caso de uso

Un banco necesita simular su fila de atención: los clientes se forman al llegar y se atienden en el mismo orden en que se formaron.

Requisitos
  • Métodos llegarCliente(nombre) y atenderCliente().
  • Consultar quién sigue con peek().
Nivel 2

Cola de impresión

Caso de uso

Una impresora compartida en la oficina recibe documentos de varios usuarios y debe imprimirlos exactamente en el orden en que fueron enviados.

Requisitos
  • Método enviarDocumento(nombre).
  • Método imprimirSiguiente() que procese el frente de la cola.
Nivel 3

Sistema de turnos por urgencia médica

Caso de uso

Un módulo de urgencias necesita atender primero a los pacientes de mayor gravedad, manteniendo dentro de cada nivel de gravedad el orden de llegada.

Requisitos
  • Una cola independiente por nivel de urgencia (por ejemplo, 3 colas).
  • Atender siempre la cola de mayor prioridad no vacía primero.
Nivel 4

Amigos de segundo grado en una red social

Caso de uso

Una red social quiere sugerir contactos mostrando primero a los amigos directos y después a los "amigos de mis amigos", en ese orden exacto de cercanía.

Requisitos
  • Recorrido BFS sobre la lista de contactos usando una cola.
  • Evitar visitar dos veces al mismo contacto.
Nivel 5

Buffer circular de un sensor IoT

Caso de uso

Un sensor de temperatura envía una lectura por segundo, pero el sistema solo necesita conservar las últimas 10 lecturas; al llegar una nueva y estar lleno el buffer, debe descartarse automáticamente la más antigua.

Requisitos
  • Cola de capacidad fija (10).
  • Al insertar con la cola llena, hacer dequeue() antes de enqueue().

Ordenamiento, búsqueda y recorrido

5 ejercicios

Elegir el algoritmo adecuado según el tamaño de los datos y si están o no ordenados.

Nivel 1

Ordenar calificaciones con burbuja

Caso de uso

Un profesor quiere mostrar la lista de calificaciones de su grupo de menor a mayor para identificar rápidamente a los alumnos con menor desempeño.

Requisitos
  • Implementar ordenamiento burbuja.
  • Imprimir el arreglo antes y después.
Nivel 2

Buscar un producto en inventario ordenado

Caso de uso

Un sistema de punto de venta tiene su catálogo de productos ordenado por código, y necesita verificar rápidamente si un código escaneado existe en el inventario.

Requisitos
  • Implementar búsqueda binaria.
  • Devolver la posición o -1 si no existe.
Nivel 3

Comparar inserción vs. burbuja por salario

Caso de uso

Recursos Humanos quiere ordenar la nómina por salario y, además, entender qué tan distinto es el número de comparaciones que hace cada algoritmo de ordenamiento sobre los mismos datos.

Requisitos
  • Implementar ambos algoritmos con un contador de comparaciones.
  • Reportar el conteo final de cada uno sobre el mismo arreglo.
Nivel 4

Lineal vs. binaria en códigos postales

Caso de uso

Un sistema de envíos necesita validar códigos postales contra un catálogo grande, y se pide comparar cuántos pasos toma encontrar un código con búsqueda lineal frente a búsqueda binaria.

Requisitos
  • Contador de pasos en ambas búsquedas.
  • Probar con un catálogo de al menos 1000 elementos ordenados.
Nivel 5

BFS y DFS en un mapa de rutas de transporte

Caso de uso

Un sistema de transporte público quiere saber si existe una ruta entre dos estaciones, explorando primero por cercanía (BFS con cola) y comparándolo contra una exploración a profundidad (DFS con pila).

Requisitos
  • Representar el mapa como una estructura de conexiones entre estaciones.
  • Implementar ambos recorridos y comparar el orden en que visitan las estaciones.

Árboles

5 ejercicios

Aprovechar la jerarquía de un Árbol Binario de Búsqueda y sus recorridos.

Nivel 1

Códigos de producto ordenados

Caso de uso

Un almacén quiere insertar sus códigos de producto en un ABB y comprobar, mediante el recorrido inorden, que efectivamente queden ordenados de menor a mayor.

Requisitos
  • Insertar al menos 8 códigos.
  • Imprimir el recorrido inorden.
Nivel 2

Buscar un empleado por número de nómina

Caso de uso

El sistema de Recursos Humanos organiza a los empleados en un ABB por número de nómina, para poder verificar rápidamente si un número existe antes de asignarlo a alguien nuevo.

Requisitos
  • Método buscar(numeroNomina).
  • Manejar el caso de árbol vacío.
Nivel 3

Altura de un árbol genealógico

Caso de uso

Una aplicación de genealogía representa a los descendientes de una persona como un árbol y necesita calcular cuántas generaciones de profundidad tiene registradas.

Requisitos
  • Método recursivo altura(nodo).
  • Caso base: nodo null devuelve 0.
Nivel 4

Árbol de decisión para diagnóstico de fallas

Caso de uso

Un manual de soporte técnico de impresoras quiere guiar a un usuario con preguntas de sí/no ("¿enciende la impresora?", "¿hay papel atascado?") hasta llegar a una posible solución.

Requisitos
  • Árbol binario donde cada nodo interno es una pregunta y cada hoja una solución.
  • Recorrido guiado por respuestas del usuario, no automático.
Nivel 5

Serializar y reconstruir categorías de un catálogo

Caso de uso

Un catálogo en línea organiza sus categorías en un ABB y necesita poder guardar esa estructura como una lista plana de texto (por ejemplo, para enviarla a otro sistema) y luego reconstruir el árbol exacto a partir de esa lista.

Requisitos
  • Serializar con recorrido preorden.
  • Reconstruir el ABB insertando los valores en ese mismo orden.

Diccionarios

5 ejercicios

Usar pares clave-valor para resolver problemas de búsqueda y conteo rápido.

Nivel 1

Agenda de contactos

Caso de uso

Una aplicación de contactos necesita guardar el número telefónico de cada persona y poder recuperarlo de inmediato escribiendo su nombre.

Requisitos
  • HashMap<String, String>.
  • Métodos para agregar, consultar y eliminar un contacto.
Nivel 2

Frecuencia de palabras en un texto

Caso de uso

Un analizador de reseñas de productos quiere saber qué palabras se repiten más en los comentarios de los clientes, para detectar quejas frecuentes.

Requisitos
  • HashMap<String, Integer> como contador.
  • Separar el texto en palabras antes de contar.
Nivel 3

Caché de cálculos costosos

Caso de uso

Un sistema realiza un cálculo matemático pesado que a veces se repite con los mismos parámetros; se necesita evitar recalcularlo guardando resultados ya obtenidos.

Requisitos
  • Diccionario que use los parámetros de entrada como clave.
  • Verificar con containsKey() antes de recalcular.
Nivel 4

Agrupar estudiantes por resultado

Caso de uso

Un profesor tiene la lista de calificaciones de su grupo y quiere separarla automáticamente en dos listas: aprobados y reprobados, para generar reportes distintos de cada grupo.

Requisitos
  • Map<String, List<Estudiante>> con claves "Aprobado"/"Reprobado".
  • Recorrer la lista original una sola vez, clasificando sobre la marcha.
Nivel 5

Traducción de códigos de error anidados

Caso de uso

Una API devuelve códigos de error agrupados por módulo del sistema (pagos, envíos, cuentas), y se necesita traducir cada código a un mensaje legible para el usuario final, organizado por módulo.

Requisitos
  • Map<String, Map<String, String>> (módulo → código → mensaje).
  • Método traducir(modulo, codigo) con manejo de módulo o código inexistente.

Conjuntos

5 ejercicios

Aprovechar la unicidad para eliminar duplicados y comparar colecciones.

Nivel 1

Eliminar correos duplicados

Caso de uso

Un boletín de noticias importó su lista de suscriptores desde varias fuentes y ahora tiene correos repetidos; se necesita quedarse solo con los correos únicos antes de enviar el próximo envío masivo.

Requisitos
  • Pasar la lista original por un HashSet<String>.
  • Reportar cuántos duplicados se eliminaron.
Nivel 2

Verificar registro de usuario

Caso de uso

Un formulario de registro necesita rechazar el registro si el nombre de usuario elegido ya está en uso por alguien más.

Requisitos
  • Conjunto de nombres de usuario existentes.
  • Verificación con contains() antes de aceptar el registro.
Nivel 3

Asistentes en común a dos eventos

Caso de uso

Los organizadores de una conferencia quieren saber qué personas asistieron tanto al evento de la mañana como al de la tarde, a partir de dos listas de asistencia independientes.

Requisitos
  • Convertir ambas listas en conjuntos.
  • Calcular la intersección con retainAll().
Nivel 4

Productos exclusivos frente a la competencia

Caso de uso

El área comercial de una tienda quiere saber qué productos de su catálogo no ofrece la competencia, comparando dos listas de productos.

Requisitos
  • Calcular la diferencia (catálogo propio − catálogo de competencia) con removeAll().
  • Mostrar el resultado ordenado alfabéticamente.
Nivel 5

Unión de etiquetas entre artículos relacionados

Caso de uso

Un blog quiere fusionar las etiquetas de dos artículos relacionados en un solo conjunto de etiquetas combinadas, sin que ninguna etiqueta quede duplicada, para mostrarlas juntas en una sección de "temas relacionados".

Requisitos
  • Calcular la unión con addAll() sobre una copia de uno de los conjuntos.
  • Mantener el conjunto original de cada artículo sin modificar.
