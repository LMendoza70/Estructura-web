Funciones recursivas, explicadas como una pila de tarjetas

Cada llamada recursiva apila una tarjeta nueva. Cuando se llega al caso base, las tarjetas empiezan a caer y a resolverse una por una. Ese es todo el modelo mental que necesitas.

01 · Idea central (técnica Feynman)

¿Qué es realmente la recursión?

Una función recursiva es una función que se llama a sí misma para resolver una versión más pequeña del mismo problema, hasta llegar a un caso tan simple que ya no necesita seguir llamándose.

Analogía: imagina un juego de muñecas rusas (matrioskas). Para saber cuántas muñecas hay en total, abres la primera y le preguntas a la de adentro "¿cuántas hay dentro de ti?". Esa le pregunta a la siguiente, y así sucesivamente, hasta llegar a la muñeca más pequeña, que no tiene ninguna adentro y responde "cero". A partir de ahí, cada muñeca suma 1 a la respuesta que recibió y se la devuelve a la de afuera.

Esa muñeca más pequeña es el caso base. El proceso de "preguntarle a la de adentro" es la llamada recursiva. Y el "sumar 1 y devolver" es lo que ocurre cuando la pila se resuelve hacia atrás.

02 · Anatomía de un método recursivo

Las dos piezas obligatorias

En Java, todo método recursivo correcto tiene exactamente estas dos partes:

1. Caso base

La condición que detiene la recursión. Sin ella, el método se llamaría a sí mismo infinitamente y provocaría un StackOverflowError.

2. Caso recursivo

La llamada al mismo método, pero con un argumento que se acerca al caso base (más pequeño, más corto, más simple).

public static int factorial(int n) {
    if (n == 0) {          // caso base
        return 1;
    }
    return n * factorial(n - 1);  // caso recursivo
}
03 · Ejemplos trabajados

Tres patrones que cubren la mayoría de los casos

Suma de los elementos de un arreglo

Reduce el arreglo en uno de tamaño n-1 en cada llamada.
public static int sumar(int[] arr, int indice) {
    if (indice == arr.length) {   // caso base: ya no quedan elementos
        return 0;
    }
    return arr[indice] + sumar(arr, indice + 1);
}

Fibonacci

Dos llamadas recursivas por invocación: crecimiento en forma de árbol.
public static int fibonacci(int n) {
    if (n <= 1) {
        return n;               // caso base
    }
    return fibonacci(n - 1) + fibonacci(n - 2);
}

Búsqueda binaria (dividir y vencer)

Cada llamada reduce el espacio de búsqueda a la mitad.
public static int busquedaBinaria(int[] a, int obj, int ini, int fin) {
    if (ini > fin) return -1;         // caso base: no encontrado
    int medio = (ini + fin) / 2;
    if (a[medio] == obj) return medio;   // caso base: encontrado
    if (a[medio] < obj)
        return busquedaBinaria(a, obj, medio + 1, fin);
    return busquedaBinaria(a, obj, ini, medio - 1);
}
04 · Errores frecuentes

Lo que suele fallar

⚠
Olvidar el caso base: el método se llama para siempre hasta agotar la pila de memoria y lanzar StackOverflowError.
⚠
El caso recursivo no se acerca al caso base: por ejemplo, llamar factorial(n) en vez de factorial(n - 1).
⚠
Recalcular lo mismo muchas veces: Fibonacci recursivo puro es exponencial; para n grandes conviene memoización o una versión iterativa.
05 · Principio de Pareto

El 20% de reglas que explica el 80% de la recursión

  • Todo método recursivo necesita al menos un caso base que no se llame a sí mismo.
  • Cada llamada recursiva debe moverse hacia el caso base, nunca alejarse de él.
  • Piensa en cada llamada como una tarjeta nueva en la pila: tiene su propia copia de las variables locales.
  • El return de una llamada recursiva alimenta el cálculo de la llamada que la invocó (la de "afuera").
  • Si puedes resolverlo fácilmente con un ciclo for, no fuerces la recursión: úsala cuando el problema es naturalmente "más pequeño de sí mismo" (árboles, divide y vencerás, backtracking).
06 · Active recall

Ponte a prueba (haz clic en cada pregunta)

1. ¿Qué pasa si un método recursivo no tiene caso base?
Se sigue llamando indefinidamente, apilando frames en la pila de llamadas hasta que Java lanza un StackOverflowError.
2. En factorial(n), ¿en qué momento se ejecuta la multiplicación n *?
No se ejecuta al momento de la llamada, sino cuando esa llamada recibe el valor de retorno de factorial(n-1), es decir, mientras la pila se "desenrolla" hacia atrás.
3. ¿Por qué Fibonacci recursivo puro es ineficiente para valores grandes de n?
Porque recalcula los mismos subproblemas muchas veces (por ejemplo, fibonacci(3) se calcula repetidamente dentro del árbol de llamadas), lo que produce complejidad exponencial.
4. ¿Qué debe cumplir el argumento en cada llamada recursiva para garantizar que el algoritmo termine?
Debe acercarse progresivamente al caso base (por ejemplo, disminuir, dividirse a la mitad, o recorrer un índice hacia el final del arreglo).
