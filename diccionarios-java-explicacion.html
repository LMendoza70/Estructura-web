Diccionarios: buscar por nombre, no por posición

En un arreglo preguntas "¿qué hay en la posición 3?". En un diccionario preguntas "¿qué hay bajo la clave "manzana"?" — y la respuesta llega casi instantáneamente, sin importar cuántos elementos existan.

Un diccionario vacío tiene sus cubetas listas para recibir pares clave-valor.

Cada clave pasa por una función hash que decide directamente en qué cubeta vive — por eso get() no necesita recorrer todo el diccionario.

01 · Concepto de diccionarios

¿Qué es un diccionario?

Un diccionario (también llamado mapa o Map) es una estructura de datos que almacena información en pares clave-valor. Cada clave es única dentro del diccionario y se usa para acceder directamente a su valor asociado, sin necesidad de un índice numérico ni de recorrer los demás elementos.

Analogía: un diccionario de español de toda la vida. No lo lees de la página 1 a la 900 para encontrar "manzana": vas directo a la sección que corresponde a esa palabra porque el libro está organizado para que la palabra misma (la clave) te lleve directo a su definición (el valor). Un diccionario en programación funciona con la misma idea, solo que la clave puede ser cualquier tipo de dato, no solo texto.
02 · Componentes

Las piezas de un diccionario

clave (key)

El identificador único que se usa para guardar y recuperar un valor. No puede repetirse dentro del mismo diccionario.

valor (value)

El dato asociado a esa clave. A diferencia de las claves, los valores sí pueden repetirse.

entrada (entry)

El par clave-valor completo, tal como vive dentro de la estructura.

función hash

Convierte la clave en un número (el índice de una cubeta), determinando en qué parte de la memoria interna vivirá esa entrada.

cubetas (buckets)

Las "casillas" internas donde caen las entradas según el resultado de la función hash — lo que ves representado arriba.

colisión

Cuando dos claves distintas producen el mismo resultado de hash y deben convivir en la misma cubeta; el diccionario las maneja internamente (por ejemplo, en una pequeña lista dentro de la cubeta).

03 · Función práctica

Dónde se usan los diccionarios para resolver problemas reales

Agenda de contactos

La clave es el nombre; el valor, el número de teléfono. Buscar un contacto es instantáneo.

Conteo de frecuencia de palabras

La clave es la palabra; el valor, cuántas veces apareció — el patrón más común para este tipo de análisis.

Caché / memorización

Se guarda el resultado de un cálculo costoso usando sus parámetros de entrada como clave, evitando repetir el trabajo.

Traducción de códigos

Convertir un código de país, de error o de moneda en su nombre completo, en un solo paso.

04 · Operaciones

Lo que se le puede hacer a un diccionario

put(clave, valor)

Agrega una nueva entrada, o reemplaza el valor si la clave ya existía.

get(clave)

Devuelve el valor asociado a esa clave, o null si no existe.

remove(clave)

Elimina la entrada correspondiente a esa clave.

containsKey(clave)

Indica si esa clave existe en el diccionario, sin necesidad de comparar con null manualmente.

import java.util.HashMap;
import java.util.Map;

Map<String, String> agenda = new HashMap<>();

// put: agregar o actualizar una entrada
agenda.put("Ana", "555-1234");
agenda.put("Luis", "555-5678");
agenda.put("Ana", "555-0000");   // reemplaza el valor anterior de "Ana"

// get: obtener un valor por su clave
String numero = agenda.get("Luis");   // "555-5678"

// containsKey: verificar existencia antes de usar el valor
if (agenda.containsKey("Marco")) {
    System.out.println(agenda.get("Marco"));
} else {
    System.out.println("Contacto no encontrado");
}

// remove: eliminar una entrada
agenda.remove("Ana");

// recorrer todas las entradas
for (Map.Entry<String, String> entrada : agenda.entrySet()) {
    System.out.println(entrada.getKey() + " -> " + entrada.getValue());
}
05 · Errores frecuentes

Lo que suele fallar

⚠
Asumir que get() lanza un error si la clave no existe: en realidad devuelve null. Si no se valida antes de usar el resultado, puede provocar un NullPointerException más adelante en el código.
⚠
Esperar un orden específico al recorrer un HashMap: el orden de iteración no está garantizado. Si el orden importa, hay que usar LinkedHashMap (orden de inserción) o TreeMap (orden por clave).
⚠
Usar como clave un objeto que puede cambiar después de insertarlo: si el contenido de la clave cambia tras el put(), su hash cambia también, y el diccionario puede "perder" esa entrada — ya no la encontrará en su cubeta original.
06 · Principio de Pareto

El 20% de reglas que explica el 80% de los diccionarios

  • Toda entrada es un par clave-valor; las claves son únicas, los valores no tienen por qué serlo.
  • La función hash convierte la clave en la posición interna donde vivirá el valor — por eso el acceso es prácticamente O(1) en promedio, sin importar el tamaño del diccionario.
  • put() agrega o reemplaza; get() consulta (y devuelve null si no existe); remove() elimina; containsKey() verifica antes de asumir.
  • Si necesitas orden garantizado al recorrer, un HashMap normal no lo ofrece: usa LinkedHashMap o TreeMap.
  • Si el problema es "necesito buscar algo por su nombre/código/identificador rápidamente", casi siempre la respuesta es un diccionario.
07 · Active recall

Ponte a prueba (haz clic en cada pregunta)

1. ¿Qué diferencia principal hay entre acceder a un elemento de un arreglo y a uno de un diccionario?
En el arreglo se accede por posición numérica (índice); en el diccionario se accede por una clave, que puede ser de cualquier tipo, no solo un número.
2. ¿Qué hace la función hash dentro de un diccionario?
Convierte la clave en un número que determina en qué cubeta interna se guardará (o se buscará) la entrada, permitiendo un acceso casi directo sin recorrer todas las entradas.
3. ¿Qué devuelve get() si la clave que buscas no existe en el diccionario?
null, no una excepción. Por eso es recomendable verificar con containsKey() antes de usar el resultado, para evitar un NullPointerException.
4. Si haces put("Ana", "555-1234") y luego put("Ana", "555-0000"), ¿cuántas entradas quedan para "Ana" y con qué valor?
Queda una sola entrada, con el valor más reciente: "555-0000". Como las claves son únicas, el segundo put() reemplaza el valor anterior en vez de crear una entrada nueva.
