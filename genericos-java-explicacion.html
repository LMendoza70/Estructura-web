Genéricos: un molde que decide su tipo al usarse

Una clase parametrizada no dice de qué tipo son sus datos. Lo dice quien la instancia. El molde es el mismo; el tipo se elige en el momento de crear el objeto.

Caja<String> caja = new Caja<>();
vacío

Cambia el tipo elegido y observa cómo Caja<T> acepta un valor distinto cada vez — pero solo del tipo que tú definiste al instanciarla.

01 · Idea central (técnica Feynman)

¿Qué es una clase parametrizada?

Una clase genérica se define con uno o más parámetros de tipo (normalmente letras como T, E, K, V) que actúan como "espacios en blanco" para un tipo de dato concreto. Ese espacio en blanco se rellena hasta el momento en que se crea una instancia.

Analogía: piensa en un molde de gelatina. El molde en sí no tiene sabor ni color; solo define la forma. Cuando alguien lo usa, elige si vierte gelatina de fresa, de limón o de uva. El molde es Caja<T>; el sabor elegido al momento de usarlo es el tipo concreto: Caja<String>, Caja<Integer>, Caja<Persona>.
02 · Parámetro de tipo vs. instanciación

Cómo se relacionan

En la clase (el molde)

T es un marcador de posición. El compilador no sabe todavía qué tipo real será; solo garantiza que, sea cual sea, se usará de forma consistente en toda la clase.

En la instancia (el uso)

Al escribir new Caja<String>(), cada aparición de T dentro de la clase se sustituye mentalmente por String para esa instancia en particular.

public class Caja<T> {

    private T contenido;

    public void guardar(T valor) {
        this.contenido = valor;
    }

    public T obtener() {
        return contenido;
    }
}

Nótese que T aparece en tres lugares: como tipo del atributo, como tipo del parámetro de guardar() y como tipo de retorno de obtener(). Los tres quedan ligados al mismo tipo concreto quien se elija al instanciar.

03 · Instanciando la misma estructura con distintos tipos

Un solo molde, muchos usos

// La misma clase Caja<T>, usada con tres tipos distintos:

Caja<String> cajaTexto = new Caja<>();
cajaTexto.guardar("Hola mundo");
String texto = cajaTexto.obtener();   // no necesita casteo

Caja<Integer> cajaNumero = new Caja<>();
cajaNumero.guardar(42);
Integer numero = cajaNumero.obtener();

Caja<Persona> cajaPersona = new Caja<>();
cajaPersona.guardar(new Persona("Ana"));
Persona p = cajaPersona.obtener();

Sin genéricos, Caja tendría que guardar Object y cada lectura necesitaría un casteo manual ((String) caja.obtener()), con el riesgo de un ClassCastException en tiempo de ejecución si alguien mete el tipo equivocado. Con genéricos, ese error se detecta en tiempo de compilación, antes de ejecutar el programa.

Más de un parámetro de tipo

public class Par<K, V> {
    private K clave;
    private V valor;

    public Par(K clave, V valor) {
        this.clave = clave;
        this.valor = valor;
    }

    public K getClave() { return clave; }
    public V getValor() { return valor; }
}

// Instanciación:
Par<String, Integer> edad = new Par<>("Luis", 34);
04 · Errores frecuentes

Lo que suele fallar

⚠
Usar el "tipo crudo" (raw type): escribir Caja caja = new Caja(); sin especificar <T> funciona por compatibilidad histórica, pero pierdes toda la seguridad de tipos: el compilador vuelve a tratar todo como Object.
⚠
Intentar usar tipos primitivos directamente: no puedes escribir Caja<int>. Los parámetros de tipo solo aceptan tipos de referencia, por eso se usa la clase envolvente: Caja<Integer>.
⚠
Mezclar tipos entre instancias: Caja<String> y Caja<Integer> son, para el compilador, dos contratos distintos: no puedes asignar una a la otra ni pasar un valor del tipo equivocado a guardar().
05 · Principio de Pareto

El 20% de reglas que explica el 80% de los genéricos

  • El parámetro de tipo (T, K, V...) es un marcador que se define en la clase y se resuelve al instanciar.
  • Una misma clase genérica puede instanciarse con tantos tipos concretos distintos como se necesite, sin duplicar código.
  • Los parámetros de tipo solo aceptan tipos de referencia: usa clases envolventes (Integer, Double, Character...) para los primitivos.
  • Los genéricos mueven la detección de errores de tipo de "en tiempo de ejecución" a "en tiempo de compilación".
  • Evita el tipo crudo (usar la clase genérica sin <...>): pierde toda la seguridad de tipos que los genéricos ofrecen.
06 · Active recall

Ponte a prueba (haz clic en cada pregunta)

1. ¿Cuándo se decide el tipo real que reemplazará a T en una clase genérica?
En el momento de crear la instancia, por ejemplo en new Caja<String>(), no cuando se escribe la definición de la clase.
2. ¿Por qué Caja<String> y Caja<Integer> no son intercambiables?
Porque, aunque provienen del mismo molde Caja<T>, cada instanciación fija un tipo distinto para T, y el compilador las trata como contratos de tipo diferentes.
3. ¿Por qué no se puede escribir Caja<int>?
Porque los parámetros de tipo en Java solo aceptan tipos de referencia (clases), no tipos primitivos. Para guardar enteros hay que usar la clase envolvente Integer.
4. ¿Qué ventaja concreta dan los genéricos frente a usar Object y castear manualmente?
Detectan errores de tipo en tiempo de compilación en lugar de en tiempo de ejecución, y eliminan la necesidad de castear manualmente al leer el valor guardado.
